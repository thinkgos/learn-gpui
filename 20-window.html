20. 窗口管理

GPUI 的窗口由 WindowOptions 配置、cx.open_window() 创建, 之后通过 Window 句柄做调整/对话框/关闭, 通过 Context<T> 的观察者订阅窗口变化.

20.1 WindowOptions 完整字段

WindowOptions 是创建窗口的配置结构体, 配合 ..Default::default() 只填需要的字段:

字段类型说明
window_boundsOption<WindowBounds>位置/状态: None 继承已有边界; Some(WindowBounds::Windowed(bounds)) 指定位置尺寸
titlebarOption<TitlebarOptions>None = 无标题栏(自绘); Some(...) 配置标题、透明标题栏、macOS 红绿灯位置
kindWindowKind窗口类型(见 20.2)
focusbool创建后是否聚焦(默认 true)
showbool创建后是否显示(默认 true, 传 false 创建隐藏窗口)
is_movablebool用户能否拖动窗口(默认 true)
is_resizablebool用户能否调整大小(默认 true)
is_minimizablebool用户能否最小化(默认 true)
app_owns_titlebar_dragbool自绘标题栏时由应用接管拖动(仅 macOS)
display_idOption<DisplayId>显示在哪个显示器(None = 主显示器)
window_backgroundWindowBackgroundAppearance窗口底色材质: Opaque/Transparent/Blurred/MicaBackdrop/MicaAltBackdrop
window_min_sizeOption<Size<Pixels>>窗口最小尺寸
window_decorationsOption<WindowDecorations>X11/Wayland 客户端或服务端装饰
iconOption<Arc<image::RgbaImage>>窗口图标(仅 X11)
app_idOption<String>应用标识, 供桌面环境分组
tabbing_identifierOption<String>macOS 原生标签页分组
use_display_p3bool用 P3 色域渲染(仅 macOS)
*_frame_intervalOption<Duration>非活跃/低电量/过热时的帧率上限(三个字段)

TitlebarOptions 的字段: title(初始标题)、appears_transparent(隐藏系统标题栏以便自绘, macOS/Windows)、traffic_light_position(macOS 红绿灯按钮位置).

#![allow(unused)]
fn main() {
// 取自 examples/window.rs: 居中开一个 800x600 的普通窗口
let bounds = Bounds::centered(None, size(px(800.0), px(600.0)), cx);
cx.open_window(
    WindowOptions {
        window_bounds: Some(WindowBounds::Windowed(bounds)), // 窗口化 + 初始位置尺寸
        ..Default::default()
    },
    |window, cx| cx.new(|cx| WindowDemo {}),
)
.unwrap();
}

NOTE: 居中要在创建前自己算好位置: Bounds::centered(None, size, cx) 或 WindowBounds::centered(size, cx), 再放进 window_bounds.
window_bounds 和 titlebar 都是 Option, window_bounds: None 表示继承已有边界, titlebar: None 表示不要系统标题栏(自绘标题栏场景, 见 window.rs 的 Custom Titlebar). WindowBounds 的变体是 Windowed/Maximized/Fullscreen, 没有 Fixed; Maximized/Fullscreen 里包的 Bounds 是恢复用的尺寸.

20.2 WindowKind 枚举

kind 决定窗口的层级和交互方式:

变体说明典型用途
WindowKind::Normal普通应用窗口(默认)主窗口
WindowKind::PopUp置顶的弹出窗口警示、弹层
WindowKind::AnchoredPopup(options)相对父窗口定位的原生弹出层, 尺寸取 window_bounds下拉菜单、右键菜单、工具提示
WindowKind::Floating浮动在父窗口之上的窗口工具面板、调色板
WindowKind::Dialog挡住父窗口交互直到关闭的模态对话框确认框
WindowKind::LayerShell(options)Wayland LayerShell 覆盖层(仅 Linux/Wayland)dock、壁纸、通知层

💡 提示: 平台差异较大 —— 同一个 kind 在 macOS/Windows/Linux 上的原生行为(聚焦策略、动画、装饰)不完全一致, 多平台实测为准. examples/window.rs 把几种 kind 各开一个窗口, 可以直观对比.

20.3 窗口操作

window.prompt() —— 系统对话框:

#![allow(unused)]
fn main() {
pub fn prompt<T: Clone + Into<PromptButton>>(
    &mut self,
    level: PromptLevel,       // Info/Warning/Critical
    message: &str,            // 主提示文字
    detail: Option<&str>,     // 补充说明, 可 None
    answers: &[T],            // 按钮列表
    cx: &mut App,
) -> oneshot::Receiver<usize>  // 异步返回被点按钮的下标
}

按钮既可以直接传 &str(仅 “ok”/“cancel” 会映射成 Ok/Cancel 按钮, 其他文字都算 Other), 也可以用 PromptButton 显式指定语义 —— 中文标签建议用后者, 保留“确定/取消“的按钮类型:

#![allow(unused)]
fn main() {
// 简单版: &str 里的 "ok"/"cancel" 自动映射成 OK/Cancel 按钮
let answer = window.prompt(PromptLevel::Info, "Are you sure?", None, &["OK", "Cancel"], cx);

// 中文按钮: 显式构造 PromptButton
let answer = window.prompt(
    PromptLevel::Info,
    "Are you sure?",
    None,
    &[PromptButton::ok("确定"), PromptButton::cancel("取消")],
    cx,
);

// 结果是异步的: 在任务里 await 出按钮下标
cx.spawn(async move |_| {
    if answer.await.unwrap() == 0 {
        println!("You have clicked Ok");
    }
})
.detach();
}

window.resize() —— 调整内容区尺寸(单位是逻辑像素 Pixels):

#![allow(unused)]
fn main() {
window.resize(size(px(1024.0), px(768.0))); // 设置内容区尺寸: 1024x768
}

窗口显示与状态控制:

方法说明
window.remove_window()关闭(销毁)这个窗口
window.minimize_window()最小化
window.zoom_window()缩放(等价于标题栏的最大化按钮)
window.toggle_fullscreen()/window.is_fullscreen()切换/查询全屏
window.activate_window()聚焦并把窗口带到前台
window.request_attention()请求系统注意力(如 Dock 闪烁)
window.bounds()/window.window_bounds()查询窗口矩形/状态(含恢复尺寸)
cx.hide()隐藏整个应用
cx.activate(ignoring_other_apps)激活应用(如恢复后重新前置)

20.4 监听窗口变化

窗口变化通过实体的 Context<T> 注册观察者, 统一返回 Subscription(保存住或 .detach() 才持续有效), 回调签名都是 |this: &mut T, window: &mut Window, cx: &mut Context<T>|:

方法触发时机
cx.observe_window_bounds(window, cb)窗口移动或缩放
cx.observe_window_activation(window, cb)窗口激活/失活
cx.observe_window_visibility(window, cb)可见性变化
cx.observe_window_appearance(window, cb)外观(亮色/暗色)变化
cx.observe_window_display(window, cb)移到别的显示器/刷新率变化
cx.observe_button_layout_changed(window, cb)标题栏按钮布局变化
 
#![allow(unused)]
fn main() {
// 取自 examples/window.rs: 在实体创建时注册一次
cx.new(|cx| {
    cx.observe_window_bounds(window, move |_, window, _| {
        println!("Window bounds changed: {:?}", window.bounds());
    })
    .detach();
    WindowDemo {}
})
}

外观用 window.appearance() 查询, 返回 WindowAppearance(Light/VibrantLight/Dark/VibrantDark, 由操作系统决定), App 级查询是 cx.window_appearance(). 需要跟随系统亮暗切换配色, 订阅 observe_window_appearance 即可.

窗口关闭的回调在 App 上: cx.on_window_closed(|cx, window_id| ...). 典型用法是“最后一个窗口关了就退出“:

#![allow(unused)]
fn main() {
cx.on_window_closed(|cx, _window_id| {
    if cx.windows().is_empty() {
        cx.quit();
    }
})
.detach();
}
