1. Hello World — 你的第一个GPUI程序

每个GPUI应用都遵循同一套骨架: 创建应用、打开窗口、运行事件循环. 本章带你写完并跑通第一个程序, 认识 Application、App、Window、Entity、Render 这几个绕不开的概念, 后面所有章节都建立在这套骨架之上.

1.1 最小GPUI程序

一个最小的GPUI程序分三步:

  1. 创建应用: gpui_platform::application() 返回当前平台的 Application.
  2. 启动事件循环: .run(|cx: &mut App| { ... }) 启动应用, 闭包在应用就绪后执行一次, 里面的cx是全局上下文.
  3. 打开窗口: 在闭包里 cx.open_window(...) 指定窗口配置和根组件, 窗口内容就是根组件 render 出来的元素树.
use gpui::{
    App, Bounds, Context, SharedString, Window, WindowBounds, WindowOptions, div, prelude::*, px,
    rgb, size,
};
use gpui_platform::application;

/// 我们要展示的"应用状态".GPUI组件就是普通 Rust 结构体,
/// 实现 `Render` trait 后, 就能描述自己长什么样.
struct HelloWorld {
    /// 要显示的文本内容. `SharedString` 是GPUI里的字符串类型, clone 很便宜.
    text: SharedString,
}

/// 实现 `Render`: 告诉GPUI这个组件的界面由哪些元素组成.
impl Render for HelloWorld {
    /// 返回值是"任意可以转换成 Element 的东西", 通常就是一棵 div() 布局树.
    /// `_window` 和 `_cx` 这里用不到, 所以用下划线开头.
    fn render(&mut self, _window: &mut Window, _cx: &mut Context<Self>) -> impl IntoElement {
        div() // 创建一个 div 元素, 类似 HTML 里的 <div>
            .flex() // 弹性布局: display: flex
            .flex_col() // 改成纵向排列: flex-direction: column
            .gap_3() // 子元素之间的间距: gap: 0.75rem (12px)
            .bg(rgb(0x505050)) // 背景色: background-color: #505050
            .size(px(500.0)) // 宽高都是 500 像素: width: 500px; height: 500px
            .justify_center() // 主轴居中(这里是垂直居中): justify-content: center
            .items_center() // 交叉轴居中(这里是水平居中): align-items: center
            .shadow_lg() // 大阴影: box-shadow: 0 10px 15px -3px rgb(0 0 0/0.1), ...
            .border_1() // 1 像素边框: border-width: 1px
            .border_color(rgb(0x0000ff)) // 边框颜色: border-color: #0000ff
            .text_xl() // 字号加大: font-size: 1.25rem; line-height: 1.75rem
            .text_color(rgb(0xffffff)) // 文字颜色: color: #ffffff
            // 子元素: 一行文字. String 直接就能当元素用
            .child(format!("Hello, {}!", self.text))
    }
}

/// 程序入口
fn main() {
    // application().run(...) 启动应用主循环, 并在闭包里做初始化
    application().run(|cx: &mut App| {
        // 计算窗口位置: 让 500x500 的窗口出现在屏幕中央(None 表示用默认显示器)
        let bounds = Bounds::centered(None, size(px(500.), px(500.0)), cx);
        // 打开一个新窗口, 第二个参数的闭包负责创建窗口的根组件
        cx.open_window(
            WindowOptions {
                window_bounds: Some(WindowBounds::Windowed(bounds)), // 用上面算好的位置和尺寸
                ..Default::default() // 其余选项都用默认值(默认自带系统标题栏)
            },
            |_, cx| {
                // cx.new(...) 创建一个实体: 状态的所有权交给 GPUI, 返回强类型句柄 Entity<T>
                cx.new(|_| HelloWorld {
                    text: "World".into(),
                })
            },
        )
        .unwrap(); // 简单示例里直接 unwrap, 失败就 panic
        // 让这个窗口成为活动窗口(抢到输入焦点)
        cx.activate(true);
    });
}

(真实示例 hello_world.rs 还做了加载字体、兼容 wasm 两件事, 与GPUI骨架无关, 这里省略.)

逐块看下来:

  • struct HelloWorld 就是组件本体, 字段就是它要显示的状态.
  • impl Render for HelloWorld 把状态翻译成界面: render 返回一棵元素树,GPUI拿去布局和绘制; 状态没变时直接跳过, 不会白跑(见 1.5).
  • application().run(...) 之后控制权就交给事件循环, 闭包只在启动时执行一次; 窗口一直开着, 直到用户退出.

💡 提示: SharedString 是GPUI的共享字符串, 内部是 SmolStr(本质为 Arc<str> 与 &'static str 的抽象), clone 只增加引用计数. render 每次重建元素树都会复制文本, 所以GPUI的文本 API 普遍收 SharedString(见 1.4).

NOTE: 应用入口是 Application 加 .run(...), 没有 App::new() 这个构造函数 —— Application 只能通过 Application::with_platform(...) 构造, gpui_platform::application() 就是“当前平台“版本的封装.

NOTE: open_window 的第二个参数是 FnOnce(&mut Window, &mut App) -> Entity<V> —— 闭包收 window 和cx两个 参数, 返回值必须是 cx.new(...) 创建出来的 Entity<V>, 不是直接返回组件本体.

NOTE: WindowOptions 的标题栏字段类型是 Option<TitlebarOptions>, 没有 WindowTitlebarOptions 这个类型. WindowOptions::default() 已经带了默认标题栏, 只改窗口位置/尺寸时 ..Default::default() 就够了.

1.2 关键概念: 一段话速认

  • Application: 应用的“启动器“. 在 main 里创建和配置(资源加载、退出策略等), 调 .run() 把控制权交给事件循环, 之后你几乎不再直接碰它.
  • App: 全局上下文, 也就是 run 闭包手里的 cx. 事件循环、所有实体、窗口、全局状态都归它管, 严格跑在主线程(见 1.1).
  • Window: 一个操作系统窗口, 也是一块独立的渲染表面. render 的第一个参数 window 就是它, 焦点、尺寸这类“窗口的事“都找它(见 1.2).
  • Entity: 被GPUI托管的状态容器. 你的结构体经 cx.new(...) 注册后成为实体, 拿到强类型句柄 Entity<T>, 谁持有句柄谁就能读写、观察它(见 1.4).
  • Render: 把“数据“升级成“视图“的 trait. 实现了 Render 的实体就能画上屏: render 按当前状态返回元素树(impl IntoElement)(见 1.5).
  • 顺带两个: Context 是传给你的 cx, 负责安全读写实体、通知重绘(见 1.3); Element 是 div() 的产物, 即界面上一个个单元.

1.3 div() 链式 API: 像写 Tailwind 一样搭界面

GPUI 的界面描述是链式调用风格: 每个修饰方法都返回 self, 一路点下去把样式、布局、子元素攒成一棵元素树. 方法名就是 Tailwind 的类名, 完全类型安全; 注释里写上等价 CSS 就能两边对照.

常用修饰方法分几类(详细清单见第 2 ~ 4 章):

分类方法示例效果
布局.flex() .flex_row() .flex_col()弹性布局及排列方向
对齐.items_center() .justify_center() .justify_between()子元素对齐: align-items/justify-content
尺寸.size() .w() .h() .flex_1()宽高与弹性伸缩
间距.p() .m() .gap()内外边距与子元素间距
颜色.bg() .text_color() .border_color()背景、文字、边框颜色
圆角.rounded_md() .rounded_lg() .rounded_full()border-radius
子元素.child() .children()添加单个/多个子元素

NOTE: 大多数样式方法的调用顺序不影响结果(各自设置独立属性), 但 .child()/.children() 的调用顺序决定子元素的排列顺序.

NOTE: 文字颜色用 .text_color(...), 没有 text_white() 这种按颜色命名的方法.

布局系统见第 3 章, 颜色阴影等样式见第 4 章, 文字排版见第 5 章; 给元素绑点击、键盘等交互见第 7 章. 本章先把骨架跑通, 这些只需点到为止.

2. 核心概念

概念说明
AppGPUI的全局单例和核心管理器, 代表了整个桌面应用程序的运行内核, 并且只在主线程使用
Window操作系统的原生窗口实体
ContextGPUI的灵魂, 可以直观地理解为 (&mut App, 当前实体/窗口引用) 的安全包装, GPUI通过传递cx(Context) 来让你安全的修改状态, 触发重绘或派发任务
EntityGPUI内存中被框架托管的强类型状态容器(类似于其他框架里的 Store Model, 或者ECS架构中的实体概念)
Element界面上可见/可交互的单元(div() 的产物), 由 render 每帧构建的一次性值, 用完即弃
Global跨窗口的应用级单例状态(主题, 设置, 连接池等)
Render/RenderOnce TraitGPUI中最核心的Trait. 当一个 Entity 实现了 Render trait 时, 它就从一个普通的数据实体升级成了“视图(View)“; 实现 RenderOnce 的只是无状态组件, 不构成视图

核心数据流:

  1. App 启动整个应用并维持生命周期.
  2. App 打开一个 Window.
  3. 你通过 Context 创建了一个结构体数据, 它成为了一个 Entity.
  4. 这个结构体实现了 Render Trait, 因此它成为了一个 View,GPUI能够调用它的 render 函数画出界面.
  5. 当用户点击按钮时, 事件触发 Context 修改了 Entity 的内部数据, 并调用 cx.notify().
  6. Context 联动 App 和 Window 触发重新渲染, 调用 Render::render, 屏幕画面随之更新.

💡 提示: 记住一句话 – GPUI不监视你的字段. 改了数据不调用 cx.notify(), 界面永远不变; 反过来 render 里不要写副作用(它可能一次都不跑, 也可能一帧跑多次).

2.1 App(全局应用)

  • 生命周期与事件循环: 管理应用的启动, 退出以及操作系统的事件循环.
  • 全局状态与注册表: 持有一个全局的 EntityMap, 管理着应用中所有的 Entity.
  • 全局单例(Globals): 允许注册和获取跨窗口共享的全局服务或配置(通过 cx.set_global 和 cx.global).
  • 异步调度: 提供后台和前台执行器(BackgroundExecutor/ForegroundExecutor), 用于派发异步任务.

NOTE: App严格运行在主线程(UI线程)上, 它不是Send的. 在开发中, 你通常不会直接裸用一个全局的App实例, 而是通过它的各种派生上下文(Context)来间接操作它.

几乎所有API都定义在 AppContext/VisualContext 两个trait上(而非直接挂在 App 上), 所以 App, Context<T>, AsyncApp 等派生上下文共用同一套方法(cx.new, cx.update_entity, …). 写可复用的辅助函数时应面向trait编程:

#![allow(unused)]
fn main() {
use gpui::{AppContext, Entity};

fn reset<C: AppContext>(count: &Entity<u64>, cx: &mut C) {
    count.update(cx, |count, cx| {
        *count = 0;
        cx.notify();
    });
}
}

NOTE: 这两个 trait 收拢的是“各上下文通用“的那部分 API, 不是全部. 全局读写的 set_global/update_global 在 BorrowAppContext 上, global::<T>() 是 App 的固有方法(Context<T> 靠 Deref 共享), AsyncApp 提供的是 read_global/update_global – 写 C: AppContext 的泛型函数时不要假设这些全局方法也在.

2.2 Window(窗口)

  • 渲染与布局宿主: 每个窗口都是一个独立的渲染表面, 负责承载该窗口内部的UI元素树和布局计算.
  • 窗口级事件处理: 管理窗口的缩放, 移动, 关闭, 最小化, 以及处理窗口级别的键盘焦点(Focus), 鼠标悬停和快捷键分发(Actions).
  • 与操作系统的桥梁: 处理系统原生的窗口装饰, 全屏切换等.

NOTE: Window 本身不是Context, 只是通常与上下文一起传递. 看 render 的签名 – window 和cx是并列的两个参数:

#![allow(unused)]
fn main() {
fn render(&mut self, window: &mut Window, cx: &mut Context<Self>) -> impl IntoElement
//                      ^^^^^^^^^^^^^^^^     ^^^^^^^^^^^^^^^^^^
//                      窗口的事(焦点/尺寸/输入)   实体的事(状态/notify/订阅)
}

窗口相关操作走 window(焦点, 尺寸, 缩放, 鼠标位置, 绘制), 实体操作走 cx. 需要同时“更新实体 + 拿到窗口“时用 entity.update_in(cx, |state, window, cx| ...).

2.3 Context(上下文)

GPUI的Context其实是一个家族, 不同回调拿到的cx类型不同:

上下文你在哪拿到它额外能力
&mut Appapplication().run 回调, 元素事件回调全部应用级能力: 实体, 窗口, 全局, 按键绑定, 平台服务
&mut Context<T>创建/更新/渲染实体 T 时notify emit observe subscribe listener spawn – 都以该实体为中心
&mut Window与上述上下文并列传递焦点, 尺寸, 缩放, 鼠标位置, 绘制
&mut AsyncAppcx.spawn 出来的future里能跨 .await 持有应用访问
&mut AsyncWindowContextcx.spawn_in 出来的future里同上, 再加一个窗口

源码上 Context<'a, T> 就是 { &mut App, WeakEntity<T> } 并 Deref<Target = App>. 所以在 Context<T> 上能直接调 App 的所有方法, 而它的实体身份让 notify() 不用再传句柄.

常用能力:

  • 状态变更与通知: 修改数据后调用 cx.notify(), 告诉 GPUI: “这个组件的数据变了, 请在下一帧重新渲染它”.
  • 订阅与响应: 允许一个 Entity 监听另一个 Entity 的事件或状态变化(cx.observe/cx.subscribe, 见 2.7).
  • 派发异步任务: 通过 cx.spawn(...) 启动一个异步 Future(例如网络请求, 文件读写), 并在完成后安全地回到UI线程更新状态.
  • 创建子实体: 通过 cx.new(|cx| ...) 在当前上下文中注册并创建一个新的 Entity.
  • 事件桥接: cx.listener(...) 把元素事件回调桥接成能拿到 &mut Self 的形式(见 2.7).

2.4 Entity 实体

  • 持有业务数据: 任何需要被GPUI管理, 响应或渲染的结构体, 都可以被注册为 Entity.
  • 句柄管理: 当你通过 cx.new(...) 创建一个结构体时, GPUI会返回一个强类型的句柄 Entity<T>(它类似于一个带类型的安全指针或ID).GPUI另外还提供弱引用 WeakEntity<T> 防止循环引用.
  • 被动响应: 由于被App托管, 其他组件可以通过 Entity 句柄去读取, 修改它, 或者监听它的变动.

值本体归 App 所有, 读写必须借助上下文:

#![allow(unused)]
fn main() {
let counter = cx.new(|_cx| Counter { count: 0 }); // 所有权交给 App
counter.update(cx, |counter, cx| {
    counter.count += 1;
    cx.notify();
});
assert_eq!(counter.read(cx).count, 1);
}

四条必知规则:

  1. 借用会panic: update 期间值被借出, 闭包里再 update 同一个实体会panic(cannot update Counter while it is already being updated). 更新别的实体没有问题, 而且是常用模式.
  2. read 的借用规则: 不能拿着 read 返回的 &T 再使用 cx(编译期拦截). 先把数据拷出来, 或把整个操作放进一个 update 里.
  3. 强弱句柄决定生死: 最后一个 Entity<T> 被drop时, 值在当前update结束时释放(先执行 cx.on_release 回调). 父子互相持有强句柄 = 循环引用泄漏, 回指一律用 WeakEntity<T>(handle.downgrade(), 访问返回 Result). 框架内部也在帮你: cx.listener 和 cx.spawn 的回调持有的是弱句柄, 按钮不会把视图拖着不放.
  4. 文本用 SharedString: 不可变且clone极便宜 – render 每帧重建元素树会大量复制字符串, 用 String 会很疼.

2.5 Render/RenderOnce(渲染特征)

  • 连接数据与UI的桥梁: 它定义了数据应当如何呈现为视觉元素.
  • 声明式描述: 在render方法中, 你不需要手动去“修改“DOM 或像素, 而是每次都通过类似 Tailwind CSS 风格的 DSL(如 div().flex().child())声明式地描述当前状态下的UI结构.

NOTE:GPUI不做DOM式的差异对比(Diffing). 元素树每帧全新构建, 用完即弃; 真正的缓存在视图层 – 上一帧渲染期间读过的数据没有被 notify 时, 该视图的 render 直接跳过, 复用上次的布局和绘制结果(见 2.9). 所以准确的说法是“视图级复用“, 而不是“元素级diff“.

签名对比才是两个Trait的本质区别:

Trait签名本质
Renderrender(&mut self, window, cx: &mut Context<Self>)有状态视图, 本质是 Entity, 跨帧存活, 靠 cx.notify() 触发更新
RenderOncerender(self, window, cx: &mut App)无状态组件, 本质是一次性值, 每帧构造-渲染-丢弃

RenderOnce::render 按值拿走 self, 且拿到的是 &mut App 而不是 Context<Self> – 它没有实体身份, 不能 notify. 想上报事件只能接收回调, 由使用它的视图决定怎么办(组件库“外观与状态分离“的由来). 配合 #[derive(IntoElement)] 后可以像元素一样使用:

#![allow(unused)]
fn main() {
use gpui::{App, SharedString, Window, div, prelude::*};

#[derive(IntoElement)]
struct Badge {
    label: SharedString,
    count: usize,
}

impl RenderOnce for Badge {
    fn render(self, _window: &mut Window, _cx: &mut App) -> impl IntoElement {
        div().flex().gap_1().child(self.label).child(self.count.to_string())
    }
}

// 使用: div().child(Badge { label: "Inbox".into(), count: unread })
}

💡 提示: 如何选择Render还是RenderOnce? 如果你的组件需要在多次渲染之间保持状态(例如: 计数器, 输入框, 展开/折叠面板), 或者需要被其他代码持有句柄, 使用 Render. 如果组件只是展示传入的数据, 不需要维护自己的状态, 使用RenderOnce更轻量.

2.6 Element 与组件体系

官方把GPUI分成三层寄存器: entity(状态)/ view(声明式UI)/ element(命令式UI). 产出UI的三种方式:

你想要写法本质
有自己状态的界面块view: 实现 Render 的类型一个Entity, 跨帧存活
无状态的可复用界面块component: 实现 RenderOnce 的类型一个值, 渲染时被消费
自定义布局/绘制element: 实现 Element 的类型一个值, 驱动帧的三个阶段

日常90%场景用 div() + fluent链式API(实现了 Styled/ParentElement/InteractiveElement). 常用技巧:

  • 条件样式: .when(cond, |el| el.bg(...)), .when_some(opt, |el, v| ...)(FluentBuilder), 不打断链式调用.
  • 分支返回不同类型: 用 .into_any_element() 擦成 AnyElement.
  • 自定义 Element: 仅在需要完全控制布局/绘制时使用(文本编辑器, 图表, 海量图元画布), 它的 request_layout/prepaint/paint 三方法对应帧的三个阶段(见 2.9); 一次性手绘用 canvas() 更省事.

ElementId – 交互元素必须有id:

#![allow(unused)]
fn main() {
div().id(("message", index)).child(...).on_click(cx.listener(...))
}

点击要跨帧记忆(“按下“发生在上一帧), 而元素每帧销毁, 这种交互状态由框架按id跨帧保存. 所以 id() 把 div() 变成 Stateful<Div>, 解锁 on_click/滚动/拖拽. 两条规则: id在兄弟间唯一; id必须稳定 – 列表会增删或排序时用内容id(如数据库id), 别用index.

2.7 notify, 事件与订阅

cx.notify() 不是“立刻重绘“, 它做两件事:

  1. 标脏窗口: 上一帧渲染时读过这个实体的窗口被标记为需要新帧(“读即依赖” – render里读了哪个entity, 就自动依赖它).
  2. 触发observers: cx.observe 注册的回调被调用.

这些效果以Effect形式排队, 直到最外层update结束才统一flush. 两个实用推论: 同一事件里 notify 三次和一次成本相同; observer一定在值不再被借出后才跑. Window::refresh() 则是“不通知任何实体, 整窗标脏“, 适合系统外观变化等外部原因.

两种事件粒度:

机制语义回调签名
cx.observe(&other, cb)“你变了”(粗粒度)cb(&mut Self, Entity<W>, &mut Context<T>)
cx.emit(event) + cx.subscribe(&other, cb)“发生了什么”(类型化)cb(&mut Self, Entity<W>, &Evt, &mut Context<T>)

emit 需要先 impl EventEmitter<Evt> for T. 一个实体可以emit多种事件, 订阅者只听到订阅的那种; 与notify一样, 事件在当前update结束后才送达.

两者都返回 Subscription, 生命周期是坑点:

  • 存进字段 -> 随实体一起死亡(推荐, 一般就是想要的语义).
  • .detach() -> 与实体解绑, 长期有效.
  • 什么都不做直接丢弃 -> 立刻退订(类型标了 #[must_use]).

cx.listener 也属于这个体系: 元素的事件回调只拿到 (&ClickEvent, &mut Window, &mut App), 不知道是哪个视图创建了它; cx.listener(|this, event, window, cx| ...) 把闭包桥接成能拿到 &mut Self 的形式, 内部持弱句柄.

2.8 Global 与异步任务

Global – 跨窗口单例状态, 本质是个marker trait:

#![allow(unused)]
fn main() {
struct Theme {
    dark: bool,
}
impl Global for Theme {}

cx.set_global(Theme { dark: false });
cx.update_global::<Theme, _>(|theme, _cx| theme.dark = true);
assert!(cx.global::<Theme>().dark);
}

选择标准: 世界上只有一个, 且与应用同寿(主题, 设置, 连接池)用 Global; 可能有多份, 或有独立生命周期的一律用 Entity. cx.observe_global::<G>() 可监听全局变更.

异步 – 重活不进UI线程:

#![allow(unused)]
fn main() {
cx.spawn(async move |this, cx| {
    // this: WeakEntity<T>, cx: &mut AsyncApp
    let data = fetch(url).await;
    this.update(cx, |this, cx| {
        this.data = data;
        cx.notify();
    })
    .ok(); // 视图可能已被释放, update 返回 Result
})
.detach(); // Task 丢弃即取消, 要后台跑完必须 detach(或持有/返回 Task)
}

NOTE: cx.spawn 返回的 Task<T> 标了 #[must_use], 丢弃会让任务立刻被取消. 后台跑完就链 .detach()(如上), 要拿返回值就把 Task 存进字段或返回给调用方.

要点: 任务拿到弱句柄(不阻止视图释放), 因此 update 返回 Result; render 和事件回调里绝不能阻塞, 网络/文件/重计算一律丢给 spawn. 需要跨await操作窗口用 cx.spawn_in(AsyncWindowContext).

2.9 帧的四阶段与视图级缓存

一次绘制走四个阶段:

阶段干什么此刻知道什么
Render视图返回元素树视图状态
Request layout每个元素提交样式规则, Taffy算出边界有样式, 没尺寸
Prepaint元素得知自己的Bounds, 注册hitbox有最终边界
Paint往场景画矩形/字形/图片, 注册事件监听边界 + hitbox

视图级缓存(retained view rendering): 视图保留上一帧的绘制结果. 窗口重绘时, GPUI只重新 render 发生了变化的视图 – “依赖“是渲染期间读过的entity/global/输入状态; 只要读过的数据都没被 notify, 该视图直接复用上次的布局和绘制输出. 改了数据但忘了 notify(或藏在 Rc<RefCell<_>>/原子量后面), 复用的视图会一直显示旧画面.

💡 提示:GPUI不是固定帧率游戏循环 – 有脏窗口或有动画才请求下一帧, 空闲即静止. render 保持无副作用, 可能跑0次也可能跑多次.

2.10 常见坑速查

坑后果解法

3. 布局系统

GPUI的布局引擎是Taffy(CSS Flexbox/Grid 规范的Rust实现), 布局概念与CSS基本一致, 但API是Tailwind风格的链式方法(定义在 Styled trait 上, div() 天然支持).

3.1 长度单位

布局 API 接受 4 种长度值:

函数类型含义对应 CSS
px(n)绝对逻辑像素, 自动适配 DPI 缩放px
rems(n)绝对根字号倍数, 默认 1rem = 16px, 跟随GPUI持有的一个基准字号设置window.set_rem_size(...)rem
relative(n)相对父容器对应轴的 0.0-1.0 比例%
auto()自动由内容/上下文决定auto

类型层次决定哪些方法收哪些值:

  • AbsoluteLength = px | rems (纯绝对值)
  • DefiniteLength = 绝对值 | relative(...) (确定值, 不含 auto)
  • Length = DefiniteLength | auto() (最宽)

规则: padding/gap 收 DefiniteLength(不能 auto), margin/宽高/定位偏移收 Length(可 auto).

#![allow(unused)]
fn main() {
div()
    .w(px(500.0))          // 固定 500px
    .h(rems(2.0))          // 2rem(默认 32px)
    .min_w(relative(0.5))  // 最小宽度为父容器的 50%
    .max_w(auto())         // 最大宽度 auto
}

NOTE:GPUI没有 fr() 函数. 比例单位是 relative(0.0-1.0); fr 语义由 flex_1()/grid_cols(n) 这类专用 API 承担. 其他教程里出现的 fr(1.0)/repeat()/minmax() 写法在 zed 的GPUI中编译不过.

3.2 Flexbox布局

Flexbox 是GPUI中最常用的布局方式. 通过.flex()启用弹性布局, 然后用方向, 对齐, 间距等修饰方法控制子元素的排列.

3.2.1 Flexbox 方向API

#![allow(unused)]
fn main() {
div()
  .flex()              // display: flex(默认 row 方向)
  .flex_row()          // flex-direction: row(水平排列, 默认值)
  .flex_col()          // flex-direction: column(垂直排列)
  .flex_row_reverse()  // flex-direction: row-reverse
  .flex_col_reverse()  // flex-direction: column-reverse

// 换行
.flex_nowrap()         // flex-wrap: nowrap(默认)
.flex_wrap()           // flex-wrap: wrap
.flex_wrap_reverse()   // flex-wrap: wrap-reverse
}

3.2.2 Flexbox 对齐API

#![allow(unused)]
fn main() {
// 交叉轴对齐(align-items)
.items_start()      // align-items: flex-start
.items_center()     // align-items: center
.items_end()        // align-items: flex-end
.items_baseline()   // align-items: baseline
.items_stretch()    // align-items: stretch

// 单个子元素覆盖交叉轴对齐(align-self)
.self_start()       // align-self: flex-start
.self_center()      // align-self: center
.self_end()         // align-self: flex-end
.self_baseline()    // align-self: baseline
.self_stretch()     // align-self: stretch

// 主轴对齐(justify-content)
.justify_start()    // justify-content: flex-start
.justify_center()   // justify-content: center
.justify_end()      // justify-content: flex-end
.justify_between()  // justify-content: space-between
.justify_around()   // justify-content: space-around
.justify_evenly()   // justify-content: space-evenly

// 多行对齐(align-content, 只在多行 flex 中有意义)
.content_normal()   // align-content: normal
.content_start()    // align-content: flex-start
.content_center()   // align-content: center
.content_end()      // align-content: flex-end
.content_between()  // align-content: space-between
.content_around()   // align-content: space-around
.content_evenly()   // align-content: space-evenly
.content_stretch()  // align-content: stretch
}

3.2.3 Flexbox 间距与弹性 API

#![allow(unused)]
fn main() {
// 子元素间距
.gap(px(8.0))       // gap: 8px(行和列)
.gap_x(px(8.0))     // column-gap: 8px
.gap_y(px(8.0))     // row-gap: 8px

// 弹性简写(子元素上使用)
.flex_1()           // flex: 1 1 0%(等分剩余空间, 忽略自身内容宽度)
.flex_auto()        // flex: 1 1 auto(可伸可缩, 基准为内容宽度)
.flex_initial()     // flex: 0 1 auto(默认, 可收缩不可拉伸)
.flex_none()        // flex: 0 0 auto(完全固定)

// 弹性细分(子元素上使用)
.flex_basis(px(120.0))  // flex-basis: 120px
.flex_grow(1.0)         // flex-grow: 1
.flex_grow_0()          // flex-grow: 0
.flex_grow_1()          // flex-grow: 1
.flex_shrink(1.0)       // flex-shrink: 1
.flex_shrink_0()        // flex-shrink: 0(禁止收缩)
.flex_shrink_1()        // flex-shrink: 1
}

💡 提示: flex_1() 和 flex_auto() 的区别 两者都会拉伸占满剩余空间, 但基准不同: flex_1() 的 flex-basis: 0% 表示无视自身内容宽度, 空间完全按 grow 系数等分(做等宽导航栏用它); flex_auto() 的 flex-basis: auto 表示先按内容宽度分配, 剩余空间再按 grow 系数分(做内容不等长的工具栏用它).

3.3 CSS Grid 布局

CSS Grid 适用于二维布局(同时控制行和列). 本版GPUI的 Grid API 是简化版: 轨道按数量统一生成(默认等分), 不支持自定义轨道列表.

#![allow(unused)]
fn main() {
div()
    .grid()             // display: grid
    .grid_rows(3)       // grid-template-rows: repeat(3, minmax(0, 1fr)) -> 3 行等分
    .grid_cols(2)       // grid-template-columns: repeat(2, minmax(0, 1fr)) -> 2 列等分
    .gap(px(16.0))      // gap: 16px
}

轨道生成规则(内部映射到 taffy):

方法内部语义说明
grid_rows(n)repeat(n, minmax(0, 1fr))n 行等分
grid_rows_min_content(n)repeat(n, minmax(min-content, 1fr))行不收缩到小于内容高度
grid_rows_max_content(n)repeat(n, minmax(0, max-content))行按内容高度撑开
grid_cols(n)repeat(n, minmax(0, 1fr))n 列等分
grid_cols_min_content(n)repeat(n, minmax(min-content, 1fr))列不收缩到小于内容宽度
grid_cols_max_content(n)repeat(n, minmax(0, max-content))列按内容宽度撑开

放置API(在 grid 子项上使用):

方法说明
col_start(n)/col_start_auto()起始列线
col_end(n)/col_end_auto()结束列线
col_span(n)/col_span_full()跨 n 列/跨满整行
row_start(n)/row_start_auto()起始行线
row_end(n)/row_end_auto()结束行线
row_span(n)/row_span_full()跨 n 行/跨满整列

示例: 2x2 仪表盘, 右侧卡片跨两行:

#![allow(unused)]
fn main() {
div()
    .size_full()
    .grid()
    .grid_rows(2) // 2 行等分
    .grid_cols(2) // 2 列等分
    .gap(px(16.0))
    .child(card("CPU"))
    .child(card("内存").row_span(2)) // 右侧跨两行
    .child(card("磁盘"))
}

NOTE: “圣杯布局”(顶栏 auto + 主区域 1fr + 底栏 auto)这类不等高行用 Grid 表达不了(轨道整组同一规则, 无法逐条混排 auto/1fr/定高), 应该用 Flex 纵向嵌套:

#![allow(unused)]
fn main() {
div()
    .size_full()
    .flex()
    .flex_col()
    .child(topbar.h(px(48.0)))    // 定高顶栏
    .child(
        div()
            .flex()
            .flex_1()             // 主区域吃掉剩余空间
            .child(sidebar.w(px(240.0)))  // 定宽侧栏
            .child(main.flex_1()),       // 主内容弹性
    )
    .child(bottombar.h(px(32.0))) // 定高底栏
}

3.4 定位系统

GPUI 支持 CSS 的 position 模型中的两种: .relative()(相对定位)和 .absolute()(绝对定位). 绝对定位的元素相对于最近的 .relative()/.absolute() 祖先定位.

NOTE:GPUI没有 .fixed() 方法(底层 taffy 支持, 但 Styled trait 未导出). 全屏遮罩/浮层的常规做法是 absolute + 四边偏移拉满.

#![allow(unused)]
fn main() {
// 定位模式
.relative()            // position: relative
.absolute()            // position: absolute

// 偏移量(配合 absolute/relative 使用, 可为负值)
.inset(px(0.0))       // 同时设置 top/right/bottom/left
.top(px(0.0))         // top: 0
.left(px(0.0))        // left: 0
.right(px(0.0))       // right: 0
.bottom(px(0.0))      // bottom: 0
.top_auto()           // top: auto
.left(px(-4.0))       // 负偏移: 常用于徽标溢出角(简写 .left_neg_1())
}

典型用法: 全屏覆盖层

#![allow(unused)]
fn main() {
div()
    .relative()             // 作为定位参考
    .size_full()
    .child(
        div()
            .absolute()         // 绝对定位
            .inset(px(0.0))     // 四边拉满
            .bg(rgba(0x00000080)), // 半透明黑色遮罩
    )
}

NOTE: rgba() 没有 rgba(色值, 透明度) 这种两参数写法, 它只收一个 8 位十六进制常量(红绿蓝 alpha 各 8 位), 如 rgba(0x00000080) 是 50% 透明的黑. 要单独调透明度用 color.alpha(0.5).

#![allow(unused)]
fn main() {

.pr(px(8.0))     // padding-right: 8px
.pb(px(8.0))     // padding-bottom: 8px
.pl(px(8.0))     // padding-left: 8px

// Margin(外边距, 支持 auto)
.m(px(16.0))     // margin: 16px
.mx(px(16.0))    // margin-left + margin-right: 16px
.my(px(8.0))     // margin-top + margin-bottom: 8px
.mt(px(8.0))     // margin-top: 8px
.mr(px(8.0))     // margin-right: 8px
.mb(px(8.0))     // margin-bottom: 8px
.ml(px(8.0))     // margin-left: 8px
.mx(auto())      // margin-left/right: auto(水平居中经典手法)

// Gap(子元素间距, Flex/Grid 容器上使用)

}

NOTE: .px() 方法是“水平 padding“, 而 px() 函数是“像素单位“ – 同名不同物. .px(px(16.0)) 里两个 px 含义完全不同, 初学容易看晕.

4. 样式与外观 - 颜色、阴影、渐变与透明度

一个好的 UI 离不开精致的视觉样式. GPUI提供了完整的样式 API, 涵盖颜色、边框、圆角、阴影、渐变、透明度等各个方面, 全部采用与 CSS 一致的命名约定, 定义在 Styled trait 上, div() 等元素直接链式调用.

4.1 颜色系统

GPUI 里颜色有两个底层类型: Hsla 和 Rgba.

  • rgb()/rgba() 返回 Rgba.
  • hsla() 和具名颜色函数返回 Hsla.
  • 所有接收颜色的样式方法都接受 impl Into<Hsla>, 两种类型可以混用.

4.1.1 rgb() - 不透明颜色

#![allow(unused)]
fn main() {
// rgb(u32) — 接受 0xRRGGBB 格式的十六进制数, alpha 恒为 1.0
rgb(0xff5733)  // 红色 0xff, 绿色 0x57, 蓝色 0x33
rgb(0x505050)  // 深灰色
rgb(0xffffff)  // 白色
rgb(0x000000)  // 黑色

// 在链式调用中使用
div()
.bg(rgb(0x7c3aed))         // 紫色背景：background-color: #7c3aed
.text_color(rgb(0xffffff)) // 白色文字：color: #ffffff
}

4.1.2 rgba() - 带透明度的颜色

#![allow(unused)]
fn main() {
// rgba(u32) — 0xRRGGBBAA 格式, 最后两位是 alpha 通道(0x00 全透明 ~ 0xff 不透明)
rgba(0x00000080)  // 半透明黑色(遮罩常用, 0x80 ≈ 50%)
rgba(0xff000033)  // 低透明度红色
rgba(0xffffff1a)  // 10% 白色(轻微高光)

// 示例: 半透明遮罩层
div()
.absolute()
.top(px(0.0))
.left(px(0.0))
.right(px(0.0))
.bottom(px(0.0))
.bg(rgba(0x00000080)) // 半透明黑色背景：background-color: rgb(0 0 0/0.5)
}

NOTE: rgba() 只收一个参数(alpha编码在十六进制数里), 不是 rgba(color, alpha) 两个参数. 想“拿一个颜色再调透明度“用 .alpha(), 见 4.1.4.

4.1.3 HSL颜色模型

#![allow(unused)]
fn main() {
// hsla(h: f32, s: f32, l: f32, a: f32)
// 四个分量都是 0.0~1.0 的小数 —— 色相 h 也是 0~1, 不是 0~360 度!
// 色相换算: 红 = 0.0, 绿 ≈ 0.333, 蓝 ≈ 0.667, 绕一圈回到红 = 1.0
hsla(0.667, 0.8, 0.5, 1.0)  // 不透明蓝色(≈ 240°)
hsla(0.333, 0.6, 0.4, 0.8)  // 80% 不透明绿色(≈ 120°)

// HSL 比 RGB 更直观: 调整亮度即可获得同色系的深浅变体
let base_hue = 0.667;  // 蓝色色相 = 240 ÷ 360
let light_blue  = hsla(base_hue, 0.8, 0.7, 1.0);  // 浅蓝
let dark_blue   = hsla(base_hue, 0.8, 0.3, 1.0);  // 深蓝
}

4.1.4 具名颜色与颜色工具

#![allow(unused)]
fn main() {
// 具名颜色函数(返回 Hsla)
gpui::black()   // #000000
gpui::white()   // #ffffff
gpui::red()     // #ff0000
gpui::green()   // #008000
gpui::blue()    // #0000ff
gpui::yellow()  // #ffff00
gpui::transparent_black()  // 完全透明的黑
gpui::transparent_white()  // 完全透明的白

// 十六进制字符串解析成 Rgba(支持 #rgb #rgba #rrggbb #rrggbbaa)
let c: Rgba = "#7c3aed".try_into().unwrap();
}

颜色值自带一组修改方法, 都返回新值而不改动原值:

#![allow(unused)]
fn main() {
let brand = rgb(0x7c3aed);

brand.alpha(0.5)      // 直接把 alpha 设成 0.5
brand.opacity(0.5)    // 把 alpha 乘以 0.5(再淡一半)
brand.grayscale()     // 去掉饱和度, 变灰
brand.blend(other)    // 把 other 按它自己的 alpha 叠加到自己上面(混色)
}

NOTE: grayscale() 只在 Hsla 上有, Rgba 没有这个方法. rgb() 返回的是 Rgba, 上面那行 brand.grayscale() 编译不过, 要灰度化得先转 Hsla(如 Hsla::from(brand).grayscale()); alpha()/opacity()/blend() 两个类型都有.

Hsla::to_rgb() 从 Hsla 转 Rgba, 反向用 Rgba -> Hsla 的 From 转换.

4.3 BoxShadow 阴影系统

GPUI 的阴影通过 BoxShadow 结构体定义, 并提供了多个预设级别供快速使用. 阴影是提升 UI 层次感的关键手段.

BoxShadow 结构体定义与构造:

#![allow(unused)]
fn main() {
pub struct BoxShadow {
    pub color: Hsla,           // 阴影颜色(通常带透明度)
    pub offset: Point<Pixels>, // 阴影偏移量 (x, y)
    pub blur_radius: Pixels,   // 模糊半径
    pub spread_radius: Pixels, // 扩散半径(可为负)
    pub inset: bool,           // true 表示内阴影
}

// 构造是"固定参数 + 链式补可选项"的建造者模式
BoxShadow::new(px(0.0), px(4.0), hsla(0.0, 0.0, 0.0, 0.1))
  .blur_radius(px(6.0))    // 模糊半径：box-shadow 的 blur 部分
  .spread_radius(px(-1.0)) // 扩散半径：box-shadow 的 spread 部分
  .inset()                 // 内阴影：box-shadow: inset ...
}

.shadow() 收的是 Vec<BoxShadow>, 可以一次叠多层阴影(列表里后面的画在更上层), .shadow_none() 清除全部阴影:

#![allow(unused)]
fn main() {
div()
.shadow(vec![
    // 同一个元素叠两层阴影: 外层大阴影 + 带颜色的小阴影
    BoxShadow::new(px(0.0), px(4.0), hsla(0.0, 0.0, 0.0, 0.3)).blur_radius(px(8.0)),
    BoxShadow::new(px(0.0), px(1.0), hsla(0.667, 0.8, 0.5, 0.4)).blur_radius(px(2.0)),
])
}

GPUI 内置了 7 个阴影预设, 从极轻微到非常明显, 数值与 Tailwind 的 shadow 刻度一致:

预设方法典型用途等价 CSS box-shadow
.shadow_2xs()细分隔线0 1px 0 0 rgb(0 0 0/0.05)
.shadow_xs()轻微浮起0 1px 2px 0 rgb(0 0 0/0.05)
.shadow_sm()按钮悬停、小卡片0 1px 3px 0 rgb(0 0 0/0.1), 0 1px 2px -1px rgb(0 0 0/0.1)

4.4 渐变背景

.bg() 不只收纯色, 渐变也是背景“填充“的一种: 用 linear_gradient() 构造, 直接传给 .bg(), 和纯色完全平权.

#![allow(unused)]
fn main() {
use gpui::{linear_color_stop, linear_gradient};

div()
.bg(linear_gradient(
    45.0, // 角度(度)：0 = 向上, 顺时针增大, 与 CSS linear-gradient 一致
    linear_color_stop(gpui::red(), 0.0),  // 起始色标：颜色 + 位置(0.0~1.0)
    linear_color_stop(gpui::blue(), 1.0), // 结束色标
))
}
  • 角度取 0~360 的度数: 0 是“从下往上“, 90 是“从左往右“, 180 是“从上往下“.
  • 目前只支持两个色标(from/to), 不支持多色标, 也没有径向(radial)/锥形(conic)渐变.
  • 两个色标位置相同(比如都写 0.5)得到的是硬边分界, 而不是渐变过渡.
  • 色标位置不必铺满 0~1, 写 0.05~0.95 会把渐变带压缩到中间, 两端各留一段纯色.

插值颜色空间:

#![allow(unused)]
fn main() {
let bg = linear_gradient(90.0, linear_color_stop(gpui::red(), 0.0), linear_color_stop(gpui::blue(), 1.0))
.color_space(ColorSpace::Oklab); // 在 Oklab 空间插值, 过渡更自然(默认 ColorSpace::Srgb)
div().bg(bg)
}

💡 提示: 为什么需要 color_space()? sRGB 线性插值的中段容易发灰发暗(红蓝渐变中间会出“脏紫色“), Oklab 在感知均匀的空间里插值, 中间色更接近人眼预期. 对比两种模式跑 cargo run --example gradient.

渐变值还能直接用在 canvas 自绘里(window.paint_path(path, gradient)), 与 .bg() 共用同一套类型, 一份渐变两处用.

4.5 图案背景

.bg() 还接受两种图案填充, 斜线网纹和棋盘格:

#![allow(unused)]
fn main() {
div().bg(pattern_slash(gpui::red(), 4.0, 4.0)) // 斜线图案：线宽 4, 间隔 4
div().bg(checkerboard(gpui::red(), 8.0))       // 棋盘格：格子边长 8
}

pattern_slash(color, width, interval) 的 width/interval 是普通 f32(不套 px()), 分别是斜线的线宽和间距; checkerboard(color, size) 的 size 是格子边长. 示例见 cargo run --example pattern.

💡 提示: .bg() 是唯一的背景入口 —— 纯色(rgb())、渐变(linear_gradient())、图案(pattern_slash()/checkerboard())三类值都走它, 可以随时互相替换.

4.6 透明度

.opacity() 修饰符控制整个元素的透明度(包括其子元素). 取值范围为 0.0(完全透明)到 1.0(完全不透明).

#![allow(unused)]
fn main() {
div().opacity(0.5) // 整个元素(含子元素)半透明：opacity: 0.5
}

与 rgba() 的区别:

  • rgba(0x00000080) 只影响背景色的透明度, 文字和子元素不受影响
  • .opacity(0.5) 影响整个元素及其所有子元素的透明度

想“只改某个颜色的透明度、不牵连子元素“, 用颜色自身的 alpha: rgba(0x00000080) 或 gpui::black().alpha(0.5). 交互状态下的悬停变淡常用状态样式回调 .hover(|style| style.opacity(0.5))(见第 7 章), 整组效果见 cargo run --example opacity.

4.7 溢出控制

当元素内容超出其限定尺寸时, 溢出控制决定如何显示多余内容.

#![allow(unused)]
fn main() {
// 隐藏溢出内容(任何元素都有)
.overflow_hidden()    // overflow: hidden(x 和 y 方向)
.overflow_x_hidden()  // overflow-x: hidden
.overflow_y_hidden()  // overflow-y: hidden

// 滚动(需要"有状态元素", 见下方 NOTE)
.overflow_scroll()    // overflow: scroll(x 和 y 都可滚)
.overflow_x_scroll()  // overflow-x: scroll
.overflow_y_scroll()  // overflow-y: scroll

// 示例: 固定高度的可滚动列表
div()
.id("list")               // 有 id 才是"有状态元素", 才能用滚动方法
.h(px(300.0))             // 固定高度：height: 300px
.overflow_y_scroll()      // 内容超过 300px 时出现纵向滚动条
.children(/* 列表项 */)
}

NOTE: overflow_hidden() 系列定义在 Styled 上, 任何元素都能用; overflow_scroll() 系列定义在 StatefulInteractiveElement 上, 只有调用过 .id(...) 的元素才有这些方法. 没有 CSS 里 overflow: auto 的对应方法 —— 只有 hidden 和 scroll 两档.

💡 提示: overflow_hidden 的常见用途 .overflow_hidden() 不仅用于隐藏溢出内容, 还常用于裁剪圆角内的子元素. 当一个元素设置了 .rounded_lg() 但子元素有背景色时, 需要给父元素加.overflow_hidden() 才能让子元素不溢出圆角. 还可以配合 .scrollbar_width(px(6.0)) 设置滚动条占的宽度.

5. 文字和排版

文字样式和布局样式一样, 都是 Styled trait 上的 Tailwind 风格方法. 与 CSS 一致, 文字属性(字号、颜色、字重等)写在容器上会继承给子元素, 所以常见做法是在父 div 上设一套基础排版, 子元素只写差异部分.

5.2 文本溢出处理

当文本超出容器边界时,GPUI提供了多种溢出处理方式:

方法说明等价 CSS
text_ellipsis()单行省略, 超出部分显示为 …text-overflow: ellipsis
text_ellipsis_start()省略开头、保留结尾(路径类文本)GPUI扩展
text_ellipsis_middle()省略中间、保留头尾(文件名类)GPUI扩展
truncate()单行截断 + 省略号, 三合一overflow: hidden + white-space: nowrap + text-overflow: ellipsis
line_clamp(n)多行省略, 最多 n 行-webkit-line-clamp: n
text_overflow(overflow)自定义截断标记GPUI扩展(见下)
whitespace_nowrap()禁止换行, 强制单行white-space: nowrap
whitespace_normal()恢复自动换行(默认)white-space: normal

几个组合的典型用法:

#![allow(unused)]
fn main() {
// 1. 三合一快捷方式: 单行截断 + 省略号
div().truncate().child(long_text)
// 等价于依次调用 overflow_hidden() + whitespace_nowrap() + text_ellipsis()

// 2. 多行省略: line_clamp(n) 只负责"最多 n 行 + 裁掉"
//    想在截断处出现 …, 还要配一个 text_ellipsis()
div().line_clamp(2).text_ellipsis().child(long_text)

// 3. 自定义截断标记(截断标记是字符串)
div().text_overflow(TextOverflow::Truncate("".into()))       // 空标记 = 直接裁掉, 什么都不显示
div().text_overflow(TextOverflow::TruncateStart("…".into())) // 从头部截, 标记补在开头
div().text_overflow(TextOverflow::TruncateMiddle("…".into())) // 从中间截, 头尾都保留
}

NOTE: 和 CSS 不同, text_ellipsis() 在GPUI里**自带“截成单行“**的效果, 不需要再配 whitespace_nowrap(). 另外 line_clamp(n) 本身只裁不加省略号, 配合 text_ellipsis() 才会在截断处显示….

NOTE: TextOverflow 是枚举, 三个变体 Truncate(marker)/TruncateStart(marker)/TruncateMiddle(marker) 分别是尾部、头部、中间截断, 其中 marker 就是截断处显示的字符串("…" 是省略号, "" 是硬裁切).

💡 提示: flex 布局里的截断 flex 子项默认会被压缩, 演示/使用截断时给盒子加 .flex_shrink_0(), 否则“被压扁“会盖过“被截断“. 不同类型文本的断行表现也值得知道: 超长英文单词不会从词中间断开, 中日韩逐字断行, URL 会在内部标点处断开. 完整对照跑 cargo run --example text_wrapper.

5.4 富文本 StyledText

一段文字里混不同样式(语法高亮、搜索命中、局部加粗), 不用拆成一堆 span, 用 StyledText 给区间套样式:

#![allow(unused)]
fn main() {
StyledText::new("ABCD").with_highlights([
    (0..1, FontWeight::EXTRA_BOLD.into()), // "A"(第 0 字节起): 特粗字重
    (2..3, FontStyle::Italic.into()),     // "C"(第 2 字节起): 斜体
])
}

with_highlights() 收一组 (Range<usize>, HighlightStyle); FontWeight/FontStyle/Hsla/Rgba 都能 .into() 变成 HighlightStyle, 也可以直接构造 HighlightStyle 一次改多样:

#![allow(unused)]
fn main() {
HighlightStyle {
    color: Some(gpui::red()),          // 文字颜色
    background_color: Some(gpui::yellow()), // 底色
    font_weight: Some(FontWeight::BOLD),   // 字重
    fade_out: Some(0.2),                   // 淡化 20%
    ..Default::default()                // 其余字段还有 font_style/underline/strikethrough
}
}

NOTE: 区间是UTF-8 字节偏移(Range<usize>), 且必须落在字符边界上. ASCII 文本可以心算, 中文/emoji 要用 s.char_indices() 之类按字节算位置, 否则会 panic.

其他构造方式:

#![allow(unused)]
fn main() {
// 1. with_runs(): 手工给每段配 TextRun(所有 run 的字节数必须正好覆盖整个字符串)
let base = window.text_style();              // 当前继承到的文字样式
let bold = base.clone().highlight(FontWeight::BOLD); // 叠加一个高亮, 变成粗体样式
StyledText::new("Hello").with_runs(vec![
    base.to_run(2), // "He": 2 个字节, 用 base 样式
    bold.to_run(3), // "llo": 3 个字节, 用 bold 样式
])

// 2. with_default_highlights(): 按给定基准样式立即算好 run
//    (与 with_highlights 二选一: 后者延迟到布局时按继承样式解析)

// 3. with_font_family_overrides(): 按区间换字体族(行内代码常见)
//    "求和 sum()" 里每个汉字占 3 字节, "sum" 落在第 7~9 字节
StyledText::new("求和 sum()").with_font_family_overrides([
    (7..10, ".ZedMono".into()), // "sum" 这 3 个字节换成等宽字体
])
}

HighlightStyle 的字段(全部 Option, 只覆盖列出的维度): color/font_weight/font_style/background_color/underline/strikethrough/fade_out.

💡 提示: 需要可点击的富文本(链接、协议勾选文本)用 InteractiveText::new(id, styled_text), 配 .on_click(ranges, listener) 按区间响应点击. 搜索框命中标黄的现成组件是 HighlightedLabel(zed ui crate).

5.5 底层文本布局 API

对于更复杂的文本渲染需求,GPUI提供了底层的文本布局 API. 这些底层 API 通常在编辑器、终端模拟器等需要精确控制字形位置的场景中使用, 一般应用场景用字符串子元素 + 文字样式即可满足需求.

#![allow(unused)]
fn main() {
/// TextRun: 一段连续的、样式相同的文本(按 UTF-8 字节数切分)
pub struct TextRun {
    /// 这段文本的 UTF-8 字节数(不含文本内容本身)
    pub len: usize,
    /// 字体(族 + 字重 + 样式 + OpenType 特性)
    pub font: Font,
    /// 颜色
    pub color: Hsla,
    /// 文字底色
    pub background_color: Option<Hsla>,
    /// 下划线
    pub underline: Option<UnderlineStyle>,
    /// 删除线
    pub strikethrough: Option<StrikethroughStyle>,
}
}

TextRun 通常不用手拼, 由 TextStyle::to_run(len) 生成(见 5.4).

#![allow(unused)]
fn main() {
/// ShapedLine: 已完成字形塑形(连字、字距调整等)的一行文本, 可直接绘制
pub struct ShapedLine { /* 排版结果 + 原始文本, text 是 pub 字段, 排版数据经 Deref 读 LineLayout */ }

impl ShapedLine {
    pub fn width(&self) -> Pixels;   // 行宽
    pub fn split_at(&self, byte_index: usize) -> (ShapedLine, ShapedLine); // 按字节切成两段
    pub fn paint(&self, origin: Point<Pixels>, line_height: Pixels,

通过窗口的文本系统做塑形:

#![allow(unused)]
fn main() {
// 单行塑形(文本里不能带 \n), 第 4 个参数是强制行宽, 一般传 None
let line = window.text_system().shape_line(text, px(16.0), &runs, None);

shape_text 返回每个软换行后的 WrappedLine, 同样有 paint()/paint_background() 可用. 渲染出来的文本元素还能拿到 TextLayout, 用 index_for_position()/position_for_index() 在“鼠标坐标 ↔ 字符下标“之间换算(编辑器选区、光标定位用).

5.6 字体

5.6.1 指定字体族

#![allow(unused)]
fn main() {
div()
    .font_family(".ZedMono")       // 字体族：font-family: ".ZedMono"
    .font_weight(FontWeight::BOLD) // 字重：font-weight: 700
}

字体族名字有两类: 以 . 开头的是GPUI内置字体(.SystemUIFont 平台 UI 字体, 是默认值; .ZedMono 等宽字体), 其余是系统安装的字体("Menlo"、"Courier New" 等). cx.text_system().all_font_names() 列出当前全部可用的字体名.

5.6.2 Font 整体设置

Font 把族名、字重、样式、OpenType 特性、回退链打包在一起, 适合一次换整套:

#![allow(unused)]
fn main() {
let f = font("Menlo")   // 以族名构造 Font
    .bold()             // 字重 700
    .italic();          // 斜体
div().font(f)           // 一次设置 family + weight + style + features + fallbacks
}

单项设置用 .font_family()/.font_weight()/.italic(), 和 .font() 是并列入口.

5.6.3 OpenType 特性与字体回退

#![allow(unused)]
fn main() {
// 关闭连字/上下文替换(calt), 代码字体常用: font-variant-ligatures: none
div().font_features(FontFeatures::disable_ligatures())
}

font_features() 接受任意 OpenType 特性标签到值的映射. 字体回退链没有独立的链式方法, 要通过 Font 的 fallbacks 字段设置(FontFallbacks::from_fonts(vec![...])), 再用 .font() 一次设入, 当首选字体缺字时按序找替代.

5.6.4 加载自定义字体

GPUI 允许通过文本系统加载自定义字体, 注意收的是字体文件的字节, 不是路径:

#![allow(unused)]
fn main() {
use std::borrow::Cow;

fn load_custom_fonts(cx: &mut App) {
    // 把 ttf 在编译期嵌进二进制, 再以字节形式注册给文本系统
    let fonts = [include_bytes!("../assets/fonts/lilex/Lilex-Regular.ttf")]
        .iter()
        .map(|b| Cow::Borrowed(&b[..]))
        .collect();

    cx.text_system().add_fonts(fonts).unwrap();
    // 之后 font_family() 里就能用这个字体的族名了
}
}

NOTE: add_fonts() 的签名是 add_fonts(Vec<Cow<'static, [u8]>>) -> Result<()>, 只接受字体文件的字节内容; 从磁盘加载要自己 std::fs::read 再转 Cow::Owned. 当前版本没有 FontSource 类型, 其他教程里 FontSource::File(PathBuf) 的写法编译不过.

💡 提示: 完整的字体示例见 cargo run --example text —— 启动时嵌入 Lilex 字体, 点顶部按钮在 .ZedMono/.SystemUIFont/Menlo/Monaco/Courier New 之间切换, 同时展示多语言字形覆盖和模块化字号阶梯.

5.7 字符网格

字符网格在网格中渲染单个字符, 常用于字体预览和调试:

/// 无状态展示组件, 用 RenderOnce 一次性消费掉自己即可
impl RenderOnce for CharacterGrid {
    fn render(self, _window: &mut Window, _cx: &mut App) -> impl IntoElement {
        div()

        .gap(px(4.0)) // 单元格间距：gap: 4px

            div()
            .size(self.cell_size)          // 单元格大小：width/height: <cell_size>

6. 图像与媒体

图像是丰富界面表达的重要元素. GPUI提供了对静态图片、SVG 、GIF 动图等多种媒体格式的支持, 并通过 AssetSource trait 提供灵活的资源加载机制.

6.1 静态图片

使用 img() 函数加载图片, 参数决定图片来源, 字符串并不等于文件路径, 这是初学者最容易搞错的地方:

写法来源说明
img("https://...")HTTP 下载能解析成 URL 的字符串走网络请求
img("assets/logo.png")AssetSource 资源键非 URL 字符串按资源键查找(见 6.4), 不是读磁盘
img(PathBuf::from("assets/logo.png"))文件系统PathBuf/&Path 直接读文件
 
#![allow(unused)]
fn main() {
use gpui::*;

fn render_images() -> impl IntoElement {
    div()
    .flex()  // 弹性布局：display: flex
    .gap_4() // 间距：gap: 16px
    .p_4()   // 内边距：padding: 16px
    // 1. URL 字符串: HTTP 异步下载
    .child(
        img("https://example.com/image.png")
        .size(px(80.0))      // 宽高 80px：width: 80px; height: 80px
        .rounded_full()      // 圆形裁剪：border-radius: 9999px
    )
    // 2. PathBuf: 直接读文件系统
    .child(
        img(PathBuf::from("assets/logo.png"))
        .size(px(100.0))
        .rounded_lg()        // 圆角：border-radius: 8px
    )
    // 3. 非 URL 字符串: AssetSource 里的资源键(见 6.4)
    .child(
        img("assets/banner.jpg")
        .w(px(200.0))        // 宽：width: 200px
        .h(px(150.0))        // 高：height: 150px
    )
}
}

img() 还有两个状态钩子和一个渲染开关:

#![allow(unused)]
fn main() {
img(PathBuf::from("assets/banner.jpg"))
    .grayscale(true) // 灰度渲染：filter: grayscale(100%)
    .with_loading(|| div().child("加载中...").into_any_element()) // 加载超过 200ms 时显示
    .with_fallback(|| div().child("加载失败").into_any_element())  // 加载失败时显示
}
  • .with_loading() 的占位元素只在加载超过 200 毫秒后才出现(常量 LOADING_DELAY), 快图不会闪占位符.
  • .with_fallback() 在加载出错时替换整个元素.
  • 两者都收一个返回 AnyElement 的闭包, 可以画任意占位/错误界面.

6.2 SVG图像

GPUI 通过 svg() 元素渲染 SVG. svg() 不收参数, 用链式方法指定来源:

方法来源
.path(key)AssetSource 资源键(见 6.4)
.external_path(path)文件系统路径, 异步读取
.data(bytes)原始 SVG 字节
 
#![allow(unused)]
fn main() {
use gpui::*;

fn render_svg() -> impl IntoElement {
    div()
    .flex()  // 弹性布局：display: flex
    .gap_4() // 间距：gap: 16px
    // 1. path(): 资源键, 通过 AssetSource 查找
    .child(
        svg()
        .path("assets/icons/settings.svg")
        .size(px(24.0))              // 宽高 24px
        .text_color(rgb(0x333333))   // 图标着色：color: #333333
    )
    // 2. external_path(): 直接读磁盘上的 SVG 文件
    .child(
        svg()
        .external_path("assets/icons/close.svg")
        .size(px(16.0))
        .text_color(gpui::red())     // 图标着色：color: #ff0000
    )
    // 3. data(): 内联的原始 SVG 字节
    .child(
        svg()
        .data(br#"<svg viewBox="0 0 24 24" xmlns="http://www.w3.org/2000/svg"><circle cx="12" cy="12" r="10" fill="currentColor"/></svg>"#)
        .size(px(32.0))
        .text_color(rgb(0x7c3aed))   // 图标着色：color: #7c3aed
    )
}
}

NOTE: SVG 在GPUI里被渲染成单色蒙版再按颜色着色, 颜色来自 .text_color(). 不设 text_color 的 SVG 什么都不画(不可见), 这和网页里 SVG 保留原配色的行为不同.

SVG 还支持只影响渲染的几何变换(不影响布局和命中测试): .with_transformation(Transformation::scale(...)/::translate(...)/::rotate(...)).

6.3 GIF动图

GPUI 原生支持 GIF 动图(以及带动画的 WebP), 不需要任何专用 API —— 帧动画自动播放:

#![allow(unused)]
fn main() {
use gpui::*;

pub struct GifViewer {
    /// GIF 文件路径
    gif_path: PathBuf,
}

impl Render for GifViewer {
    fn render(&mut self, _window: &mut Window, _cx: &mut Context<Self>) -> impl IntoElement {

6.4 AssetSource trait 自定义资源加载策略

img("资源键") 和 svg().path("资源键") 查找的资源来自 AssetSource. 通过实现这个 trait, 可以自定义资源加载策略(文件系统、嵌入内存、网络都行):

#![allow(unused)]
fn main() {
use gpui::{AssetSource, SharedString};
use std::borrow::Cow;
use std::path::PathBuf;

/// 从文件系统加载资源的 AssetSource 实现
pub struct FsAssetSource {
    /// 资源根目录
    root: PathBuf,
}

impl AssetSource for FsAssetSource {
    // 加载资源: 返回文件字节(图片/SVG 都是二进制, 不是字符串)
    fn load(&self, path: &str) -> anyhow::Result<Option<Cow<'static, [u8]>>> {
        let data = std::fs::read(self.root.join(path))?;
        Ok(Some(Cow::Owned(data)))
    }

    // 列出某目录下的资源名
    fn list(&self, path: &str) -> anyhow::Result<Vec<SharedString>> {
        Ok(std::fs::read_dir(self.root.join(path))?
            .filter_map(|entry| entry.ok())
            .map(|entry| SharedString::from(entry.file_name().to_string_lossy().to_string()))
            .collect())
    }
}
}

在应用启动时注册:

fn main() {
    application()
    .with_assets(FsAssetSource { root: PathBuf::from("assets") }) // 注册资源加载器
    .run(|cx: &mut App| {
        // 之后 img("assets/logo.png") 就会从 assets/ 目录读
    });
}

NOTE: load() 收 &str 返回字节的 Cow, 不是 SharedString —— 图片和 SVG 都是二进制. 没注册 AssetSource 时资源键一律解析失败(图片报“资源不存在“错误, SVG 什么都不画), 但 img(PathBuf) 和 img("https://...") 不受影响.

完整示例: cargo run --example image_loading(资源加载 + 自定义异步 Asset + 加载/失败占位), cargo run --example opacity(以示例目录为资源根).

6.6 图片缓存

GPUI 的图片缓存分三层, 一般用默认配置就够:

层机制何时需要关心
资源缓存img() 加载结果自动缓存, 同一来源不重复解码; 手动管理用 cx.remove_asset::<ImgResourceLoader>(&source) 强制重新加载想“重新加载“时
图片缓存RetainAllImageCache::new(cx) 手动管理, 或用 image_cache(...) 元素给整棵子树套一个自定义缓存(如 LRU)大量缩略图、要控制内存时

  • 自动缓存: 通过 img() 加载的图片会自动缓存.
  • 异步加载: 图片异步解码, 不阻塞 UI 线程; 加载完成后自动重绘.
  • 内存管理: 手动缓存(RetainAllImageCache/自定义 ImageCache)负责决定何时淘汰, 淘汰时记得 cx.drop_image() 释放纹理.

6.7 ObjectFit, 图片适配模式

⚠️ 注意: 大图加载性能注意事项

加载大尺寸图片时需要注意以下几点:

  • 异步解码:GPUI会异步解码图片, 但超大图片(>10MB)仍可能导致内存峰值.
  • 缩略图优先: 在列表或网格中显示时, 优先使用缩略图而非原图.
  • 延迟加载: 对于不可见区域的图片, 考虑延迟加载以减少启动时的内存开销.
  • GIF 优化: GIF 动图会持续占用内存和 CPU 资源, 避免在同一视图中加载过多 GIF.

7. 事件管理

事件处理是构建交互式界面的核心. GPUI提供了完整的事件系统, 涵盖鼠标、键盘等交互, 并支持事件传播控制. 本章将介绍GPUI中各种事件的监听与处理方式.

7.1 事件监听基础

所有事件处理器的回调都是统一形状: 闭包收三个参数 (event, window, cx):

#![allow(unused)]
fn main() {
// 普通闭包: |event: &E, window: &mut Window, cx: &mut App|
div().on_mouse_move(|event, _window, cx| {
    // event 是事件对象, window 是窗口, cx 是全局应用状态
})

// 配合实体状态用 cx.listener: 闭包收四个参数, 多了第一个 &mut Self
div().id("button").on_click(cx.listener(|this, _event, _window, cx| {
    this.open = !this.open; // 直接改组件状态
    cx.notify();            // 通知GPUI重新渲染
}))
}

NOTE: cx.listener 的闭包是四个参数 (this, event, window, cx), 其中 window 在第三位.

另一个重要区分: 某些处理器需要有状态元素(先调 .id(...) 才有):

需要 .id(...)任意元素可用
on_click on_aux_clickon_mouse_down on_mouse_up on_mouse_move
on_drag on_hover active()on_mouse_down_out on_scroll on_drop
tooltip() focusable() overflow_scroll()on_key_down on_action hover() …

7.2 点击事件

.on_click 监听点击, 需要有状态元素; 通常搭配 cx.listener() 修改组件状态:

#![allow(unused)]
fn main() {
div()
    .id("toggle") // on_click 需要有状态元素
    .on_click(cx.listener(|this, event, _window, cx| {
        if event.is_right_click() {
            return; // 右键不切换
        }
        this.open = !this.open;
        cx.notify();
    }))
    .child("点我切换")
}

ClickEvent 是一个枚举, 三种来源都会合成点击:

变体触发方式
Mouse在元素上按下 + 释放同一鼠标键
Keyboard元素获得焦点后按 Enter/Space
Touch触屏轻点

它不是公开字段的结构体, 要用方法取值: event.position() 位置、event.is_right_click() 右键、event.is_secondary() 次要操作(右键或长按)、event.click_count() 连击次数. 非左键的点击走 .on_aux_click()(同样需要 .id).

7.3 鼠标事件

GPUI 提供了完整的鼠标事件 API(回调形状都是 (event, window, cx)):

事件说明备注
.on_mouse_down(MouseButton::Left, l)指定键按下第一参数指定按键
.on_mouse_up(MouseButton::Left, l)指定键释放
.on_any_mouse_down(l)任意键按下
.on_mouse_move(l)鼠标在元素上移动
.on_mouse_down_out(l)鼠标在元素外按下见 7.5
.on_mouse_up_out(MouseButton::Left, l)鼠标在元素外释放
.on_scroll(l)滚轮/触控板滚动
.on_mouse_exit(l)鼠标移出窗口(不是移出元素)

NOTE: 进出元素的通知用有状态的 .on_hover(|entered: &bool, window, cx| ...)(见 7.4), 样式变化用 .hover(|style| ...)(见 7.4). 旧的 .on_scroll_wheel() 已改名为 .on_scroll().

常用事件对象的字段:

#![allow(unused)]
fn main() {
// MouseDownEvent: button 按键/position 位置/modifiers 修饰键/click_count 连击数
div().on_mouse_down(MouseButton::Left, |event: &MouseDownEvent, _window, _cx| {
    let pos = event.position;   // 鼠标位置(Point<Pixels>)
    let mods = event.modifiers; // ctrl/shift/alt/cmd 状态
})

// ScrollEvent: delta 滚动增量(像素或行数)
div().on_scroll(|event: &ScrollEvent, _window, _cx| {
    match event.delta {
        ScrollDelta::Pixels(p) => { /* 精确滚动(触控板) */ }
        ScrollDelta::Lines(l) => { /* 行滚动(滚轮) */ }
    }
})
}

MouseButton 的取值: Left/Right/Middle/Navigate(Back | Forward).

7.4 悬停与按压效果

悬停/按压是样式回调(改样式, 不是事件处理):

#![allow(unused)]
fn main() {
div()
    .id("button")                       // active() 需要有状态元素
    .hover(|s| s.bg(rgb(0x3a3a3a)))     // 悬停时的样式(任意元素可用)
    .active(|s| s.bg(rgb(0x1a1a1a)))    // 鼠标按住时的样式(需要 .id)
    .on_click(cx.listener(|_this, _event, _window, cx| {
        cx.notify();
    }))
    .child("按钮")
}
  • .hover(|style| ...)/.active(|style| ...) 收一个“样式变换“闭包, 参数是 StyleRefinement, 作用类似 Tailwind 的 hover:/active: 变体.
  • .group_hover("组名", ...)/.group_active("组名", ...) 让同组(.group("组名"))的兄弟元素一起响应.
  • 要在悬停开始/结束时做事情(而不只是换样式), 用有状态的 .on_hover(|entered: &bool, window, cx| ...), true 进入、false 离开.

7.5 鼠标按下外部检测

.on_mouse_down_out() 用于检测鼠标在元素外部按下, 常用于关闭弹出层、下拉菜单等场景. 它工作在捕获阶段, 即使内部元素拦截了事件也能触发:

#![allow(unused)]
fn main() {
use gpui::*;

pub struct Popover {
    open: bool,
}

impl Render for Popover {
    fn render(&mut self, _window: &mut Window, cx: &mut Context<Self>) -> impl IntoElement {
        div()
        .relative()
        .on_mouse_down_out(cx.listener(|this, _event, _window, cx| {
            // 点击弹出层外部时关闭
            this.open = false;
            cx.notify();
        }))
        .child(
            div()
            .id("toggle") // on_click 需要有状态元素
            .on_click(cx.listener(|this, _event, _window, cx| {
                this.open = !this.open;
                cx.notify();
            }))
            .child(if self.open { "关闭" } else { "打开" })
        )
    }
}
}

💡 提示: 弹层嵌套时(弹层里还有弹层), 里层打开时要暂时摘掉外层的 on_mouse_down_out, 否则点里层会把两层一起关掉. 完整实现(嵌套弹层 + 浮层定位)见 cargo run --example popover.

7.6 事件传播

GPUI 的事件分两个阶段, 相当于 DOM 的捕获/冒泡:

阶段鼠标事件键盘事件
捕获(Capture)按绘制顺序从前到后(先绘制的底层元素 → 后绘制的顶层元素); 所有注册了监听器的元素都会收到, 需自行用 hitbox 判断是否命中沿 dispatch tree 路径从根 → 焦点元素
冒泡(Bubble, 默认)按绘制顺序从后到前(顶层元素 → 底层元素); 通常只处理命中的最顶层元素, 可 cx.stop_propagation() 阻止继续传递沿 dispatch tree 路径从焦点元素 → 根
“层级“的依据paint order(视觉层叠)focus path(焦点祖先链)
 
    [ 窗口根节点 (Root / Window) ]
             /               \
            v  (1. 捕获阶段)   ^  (2. 冒泡阶段)
      [ 中间父容器 Div ]       | 
          /                  |
         v                   |
   [ 目标/焦点子 Div ] --------+

键盘事件按 dispatch tree 的路径, 它没有“屏幕位置“, 目标是当前焦点元素. GPUI 维护一棵 dispatch tree, 取从根到焦点节点的路径:

```Root -> Workspace -> Pane -> Editor(focused)`

  • Capture: 沿路径从根走到焦点元素
  • Bubble: 从焦点元素走回根

默认情况下事件一路冒泡, 调用 cx.stop_propagation() 可以阻止事件继续传播; cx.propagate() 则相反, 用于“处理了但还想让别人也看到“(动作处理有默认消费行为, 见 9.4):

#![allow(unused)]
fn main() {
div().on_mouse_down(MouseButton::Left, |event, _window, cx| {
    if event.modifiers.control {
        cx.stop_propagation(); // ctrl+点击不再传给父元素
    }
})
}
#![allow(unused)]
fn main() {
// window.prevent_default(): 阻止默认行为(目前主要用于"按下时不让父元素抢焦点")
}

7.7 拖放

拖放由三组 API 构成: 拖拽源 .on_drag()、放置目标 .on_drop()、拖拽中的跟踪 .on_drag_move():

#![allow(unused)]
fn main() {
// 拖拽源(需要 .id): 第一个参数是拖拽携带的数据,
// 第二个参数是构造"拖拽影子"视图的闭包(跟鼠标走的那个小窗)
div()
    .id(("item", index))
    .cursor_move() // 拖拽光标: cursor: move
    .on_drag(item_data, |data: &ItemData, offset, _window, cx| {
        cx.new(|_| DragGhost { data: data.clone(), offset })
    })

// 放置目标(普通元素即可): 松手时收到拖拽数据
div()
    .on_drop(cx.listener(|this, data: &ItemData, _window, _cx| {
        this.dropped = Some(data.clone());
    }))
}
  • 拖拽数据是任意 'static 类型, on_drop 只在“拖拽数据类型匹配“时触发.
  • .can_drop(|data: &dyn Any, window, cx| -> bool) 给放置目标加过滤条件.
  • .drag_over::<T>(|style, data, window, cx| ...) 在有匹配拖拽悬停时改放置目标的样式(高亮提示).
  • 拖拽开始后移动超过 2 像素才算拖拽; .on_drag_move(|event: &DragMoveEvent<T>, ...) 收到拖拽期间的所有移动(包括移出元素后).

完整示例: cargo run --example drag_drop.

7.8 鼠标压力

压感设备(如力度触控板)的压力是独立事件, 不是鼠标事件的字段:

#![allow(unused)]
fn main() {
div().on_mouse_pressure(cx.listener(|this, event: &MousePressureEvent, _window, cx| {
    this.pressure = event.pressure; // 压力值 0.0~1.0
    this.stage = event.stage;       // Zero/Normal/Force 三档
    cx.notify();
}))
}

NOTE: 压力走 MousePressureEvent(目前仅 macOS 力度触控板实现). 触屏的压力在 TouchEvent.force 里. 完整示例: cargo run --example mouse_pressure.

8. 焦点管理

焦点管理是构建可访问 GUI 应用的关键. GPUI提供了完善的焦点系统, 支持键盘导航、Tab 切换和程序化聚焦.

8.1 FocusHandle: 创建和管理焦点

FocusHandle 是GPUI焦点系统的核心, 每个可聚焦的元素都通过 FocusHandle 来管理焦点状态. 用 cx.focus_handle() 创建, 用 .track_focus() 绑到元素上:

#![allow(unused)]
fn main() {
use gpui::*;

pub struct Button {
    focus_handle: FocusHandle,
}

impl Button {
    pub fn new(cx: &mut Context<Self>) -> Self {
        Self {
            focus_handle: cx.focus_handle(), // 创建焦点句柄
        }
    }
}

impl Render for Button {
    fn render(&mut self, _window: &mut Window, cx: &mut Context<Self>) -> impl IntoElement {
        div()
        .track_focus(&self.focus_handle) // 绑定句柄: 元素可聚焦, 焦点样式生效
        .on_click(cx.listener(|this, _event, window, cx| {
            this.focus_handle.focus(window, cx); // 点击时把焦点移过来
        }))
        .child("按钮")
    }
}
}

FocusHandle 常用方法:

方法说明
cx.focus_handle()创建焦点句柄
handle.focus(window, cx)把焦点移到这个句柄
handle.is_focused(window)这个句柄是否持有焦点
handle.contains_focused(window, cx)自己或子孙持有焦点(焦点是否在容器内)
handle.within_focused(window, cx)自己是否位于焦点元素内部
handle.tab_index(n)/handle.tab_stop(b)链式设置 Tab 顺序(见 8.3)
window.blur(cx)清除焦点(谁都不聚焦)
window.focused(cx)当前持有焦点的句柄(Option<FocusHandle>)

8.2 焦点样式: focus() 与 focus_visible()

focus() 和 focus_visible() 是两个样式方法(定义在元素上, 配合 .track_focus() 生效), 对应 CSS 的 :focus 和 :focus-visible:

方法什么时候生效典型用途
.focus(|s| ...)元素持有焦点(不管怎么来的)搜索框聚焦时显示边框
.focus_visible(|s| ...)元素持有焦点且最后一次输入来自键盘键盘导航时才显示焦点框
.in_focus(|s| ...)元素位于焦点元素内部整个卡片内的控件一起高亮
 
#![allow(unused)]
fn main() {
div()
    .track_focus(&self.focus_handle)
    .focus(|s| s.border_2().border_color(gpui::blue()))        // 聚焦: 蓝框
    .focus_visible(|s| s.border_4().border_color(gpui::red())) // 键盘聚焦: 红粗框
    .child("按钮")
}

NOTE: focus_visible() 区分的是输入方式(键盘还是鼠标), 不是“程序聚焦 vs 键盘聚焦“. GPUI记录最近一次输入设备: 鼠标点击聚焦后不显示焦点框, Tab 导航聚焦才显示 —— 这正是 CSS :focus-visible 的语义.

三种样式对照的完整示例: cargo run --example focus_visible.

8.3 Tab 导航

GPUI 内置支持 Tab 键导航: 每帧渲染时收集所有焦点句柄排成“Tab序“, window.focus_next()/window.focus_prev() 就在序列里前进/后退. 自定义顺序和行为的开关:

方法说明
.tab_index(n)Tab 顺序编号, 从小到大; 相同则按元素出现顺序
.tab_stop(false)保留顺序位置, 但 Tab 到不了(只能程序聚焦)
.tab_group()子树自成一组, 子元素的 tab_index 从 0 重新计

.tab_index(n)/.tab_stop(b) 既有元素版(div().tab_index(1).tab_stop(true))也有句柄版(cx.focus_handle().tab_index(1).tab_stop(true)), 效果一致; .tab_group() 没有句柄版, 只能用在元素上. 典型的 Tab 键绑定写法(动作定义见第 9 章):

#![allow(unused)]
fn main() {
actions!(example, [Tab, TabPrev]);

// 绑定: tab 前进, shift-tab 后退
cx.bind_keys([
    KeyBinding::new("tab", Tab, None),
    KeyBinding::new("shift-tab", TabPrev, None),
]);

// 根元素上监听并转成焦点移动
div().track_focus(&self.focus_handle)
    .on_action(cx.listener(|_this, _: &Tab, window, cx| window.focus_next(cx)))
    .on_action(cx.listener(|_this, _: &TabPrev, window, cx| window.focus_prev(cx)))
}

完整示例(六个不同 tab 设置的按钮 + tab group): cargo run --example tab_stop.

8.4 焦点在容器内: contains_focused

想知道“焦点是不是落在我这个容器里“(比如工具栏里任意控件聚焦时工具栏高亮), 用句柄的 contains_focused:

#![allow(unused)]
fn main() {
// 判断版: 焦点在容器内时改任意逻辑
if self.toolbar_focus.contains_focused(window, cx) {
    // ...
}
}

样式版 .in_focus(|s| ...) 是反方向(元素位于焦点元素内部, 见 8.2), 不是 contains_focused 的样式写法:

#![allow(unused)]
fn main() {
// 反方向: 元素位于焦点元素内部时高亮, 不是"焦点在容器内"
div().track_focus(&self.toolbar_focus)
    .in_focus(|s| s.bg(rgb(0x2a2a2a)))
}

8.5 焦点事件

需要在焦点进出时执行逻辑(而不仅是换样式), 用以下订阅方法. 它们都返回 Subscription, 要保存住(或 .detach())才持续有效:

方法说明
cx.on_focus_in(&handle, window, l)焦点进入句柄或其子孙时触发
cx.on_blur(&handle, window, l)该句柄失去焦点时触发
cx.on_focus_out(&handle, window, l)焦点离开句柄及其子孙时触发
cx.on_focus_lost(window, l)窗口内谁都没有焦点时触发(适合选默认焦点)

9. 动作和快捷键

动作(Actions)是GPUI中解耦组件间通信的核心机制. 通过动作系统, 可以将键盘快捷键、菜单项和按钮点击统一关联到同一个处理逻辑.

9.1 actions! 宏

使用 actions! 宏定义动作类型. 它为每个名字生成一个零大小的单元结构体并自动注册:

#![allow(unused)]
fn main() {
// 带命名空间的形式(推荐): 生成 example::Quit 等动作
actions!(example, [Quit, CloseWindow]);

// 不带命名空间的形式
actions!([Quit]);
}

展开后等价于:

#![allow(unused)]
fn main() {
#[derive(Clone, PartialEq, Default, Debug, gpui::Action)]
#[action(namespace = example)]
pub struct Quit; // 单元结构体: 无字段, 无数据
}

9.2 带数据的动作

需要携带数据的动作, 直接在普通结构体上 #[derive(Action)], 字段就是普通字段, 构造用结构体字面量:

#![allow(unused)]
fn main() {
#[derive(Clone, PartialEq, Debug, serde::Deserialize, schemars::JsonSchema, Action)]
pub struct SelectNext {
    pub replace_newest: bool, // 普通字段, 直接读写
}

// 构造就是普通结构体字面量
let action = SelectNext { replace_newest: true };
}

带字段的 derive 要求结构体同时实现 serde 与 schemars 相关 trait; 不需要 JSON 序列化时在结构体上加 #[action(no_json)]. 可用属性还有 namespace = ...、name = "..."、deprecated = "..." 等.

9.3 键盘绑定

使用 cx.bind_keys() 和 KeyBinding::new() 将快捷键绑定到动作:

#![allow(unused)]
fn main() {
cx.bind_keys([
    KeyBinding::new("cmd-w", CloseWindow, None), // 快捷键 -> 动作
    KeyBinding::new("cmd-q", Quit, None),
]);
}

KeyBinding::new(keystrokes, action, context) 收三个参数:

参数说明
keystrokes: &'static str快捷键描述串(语法见下表)
action: A动作值(如 Quit), 不是引用
context: Option<&str>键位生效的上下文谓词, 如 Some("editor"), None 为全局

快捷键语法是 [修饰键-...]键名, 修饰键可以多个连写:

修饰键格式说明
Ctrlctrl-Control 键
Shiftshift-Shift 键
Altalt-Option/Alt 键
Cmdcmd-平台主键(macOS 是 Command)
别名super- win-同 cmd-
Fnfn-Fn 键
跨平台secondary-macOS 映射 cmd-, 其他平台映射 ctrl-(见下方 NOTE)

键名直接写小写字符或键位名: "ctrl-c"、"cmd-s"、"shift-escape"、"f12"、"tab"、"enter"、"space"、"left" 都合法; 大写字母隐含 Shift("ctrl-X" 等价 ctrl-shift-x); 尾部的 "-" 表示减号键. 多键序列用空格分隔: "ctrl-b h" 先按 ctrl-b 再按 h.

NOTE: KeyBinding::new() 里的快捷键串写错会直接 panic, 写完跑一下确认能启动. 上表的 secondary- 也没有办法用在 KeyBinding::new() 里(它按平台无关方式解析, 遇到 secondary- 直接报错 panic), 只有 KeyBinding::load 这类按宿主 OS 解析的入口才支持; 要跨平台就自己写 cfg!(target_os = "macos") 分支挑一套键位.

上下文绑定配合元素上的 .key_context():

#![allow(unused)]
fn main() {
// 只在 key_context 为 "TextInput" 的子树里生效
cx.bind_keys([KeyBinding::new("backspace", Backspace, Some("TextInput"))]);

div().key_context("TextInput").track_focus(&self.focus_handle) ...
}

9.4 监听动作

使用 .on_action() 在组件内监听动作. 动作会沿焦点路径冒泡, 直到被处理:

#![allow(unused)]
fn main() {
actions!(example, [CloseWindow]);

// 元素上监听: 闭包 (action, window, cx)
div()
    .track_focus(&self.focus_handle) // 焦点在哪, 动作就从哪冒泡
    .on_action(|_: &CloseWindow, window, _cx| {
        window.remove_window(); // 处理动作
    })
}

全局处理(不在元素上)用 cx.on_action, 闭包只有两个参数:

#![allow(unused)]
fn main() {
cx.on_action(|_: &Quit, cx| cx.quit()); // 全局处理
}

事件的传播顺序(和第 7 章同一套捕获/冒泡机制): 捕获(根 → 焦点元素) → 冒泡(焦点元素 → 根) → 全局处理器.

NOTE: 冒泡阶段的动作处理器默认消费动作(阻止继续冒泡). 想让父元素或全局 cx.on_action 也收到, 处理器里要调 cx.propagate(); 反过来 cx.stop_propagation() 可以提前截断. 全局处理器排在冒泡最后, 只有前面没人处理(或有人 propagate())才轮到它.

9.5 手动分发动作

使用 cx.dispatch_action() 可以手动分发动作到当前焦点元素, 动作会沿着焦点路径向上冒泡:

#![allow(unused)]
fn main() {
// 发给当前焦点元素(最常用)
cx.dispatch_action(&CloseWindow);

// 另外两个入口:
// window.dispatch_action(Box::new(CloseWindow), cx)  —— 窗口级, 发给焦点元素
// focus_handle.dispatch_action(&CloseWindow, window, cx) —— 发给指定句柄的元素
}

dispatch_action() 的分发机制:

  • 动作从当前焦点元素开始
  • 沿着视图树向上冒泡到父元素
  • 第一个处理该动作的 .on_action() 会消费它
  • 未被处理的动作会被丢弃

cx.is_action_available(&action) 可以探测当前焦点上下文里有没有处理器(用于菜单置灰).

9.6 菜单与动作

菜单项就是“另一个动作触发器“ —— 通过 cx.set_menus() 设置菜单栏, 每个菜单项挂一个动作, 点菜单等价于分发动作:

#![allow(unused)]
fn main() {
use gpui::*;

actions!(set_menus, [Quit, ToggleCheck]);

cx.on_action(|_: &Quit, cx| cx.quit());
cx.on_action(|_: &ToggleCheck, _cx| { /* 切换状态 */ });

cx.set_menus([Menu::new("File").items([
    MenuItem::action("Toggle Check", ToggleCheck).checked(true), // 可勾选项
    MenuItem::separator(),                                     // 分隔线
    MenuItem::action("Disabled", gpui::NoAction).disabled(true), // 置灰项(NoAction 占位)
    MenuItem::submenu(Menu::new("Mode").items([                 // 子菜单
        MenuItem::action("List", ToggleCheck),
    ])),
    MenuItem::action("Quit", Quit),
])]);
}

gpui::NoAction 是一个“什么都不做“的内置动作, 常用来做置灰占位菜单项. 完整示例: cargo run --example set_menus.

NOTE: cx.set_menus() 的菜单栏只在 macOS 显示 —— macOS 平台层会建 NSMenu 挂到系统菜单栏; Linux 平台层只是把菜单树存进内存(cx.get_menus() 取得回来), 没有任何东西画它, 也没接任何 Linux 菜单协议(X11 的 dbusmenu、Wayland 的 appmenu 都没有). 所以在 Ubuntu + niri/GNOME/KDE 下跑 cargo run --example set_menus 看不到菜单栏是正常现象, Linux 上没有 set_menus 的等价显示. 想在 Linux 上触发这些动作, 走下面 💡 提示里的另外两条触发源: 快捷键(注意 cmd- 在 Linux 映射到 Super 键, 会和 niri 这类合成器的快捷键撞车, 建议写 ctrl- 系列)和按钮(cx.dispatch_action).

💡 提示: 同一个动作接三个触发源 —— 快捷键(KeyBinding)、菜单(MenuItem::action)、按钮(cx.dispatch_action), 处理逻辑只写一份(.on_action), 这就是动作系统的设计初衷. 键盘 + 焦点 + 动作串起来的完整小应用见 cargo run --example focus_visible 和 cargo run --example input(文本编辑的全套动作绑定).

9.7 动作方法速查表

10. 文本输入

文本框是最常用的控件, 但GPUI没有内置的输入框组件 —— 既没有 TextInput::new(), 也没有现成的 <input>. 想要一个能打字的文本框, 得自己把三块拼起来: 实现 EntityInputHandler 接住键盘和输入法, 写一个自定义 Element 负责排版和绘制, 再把两者接到窗口的输入链路里.

10.1 概述: 一个输入框由什么组成

10.2 EntityInputHandler trait

EntityInputHandler 是GPUI文本输入的核心 trait: 实体实现它之后, 键盘输入、输入法(IME)组合、系统级的复制粘贴都会回调进来. 平台层真正接触的是 InputHandler trait, EntityInputHandler 面向实体(省掉手动 update 的样板), 由 ElementInputHandler 包一层转成 InputHandler (见 10.6).

所有 range/offset 都是 UTF-16 码元偏移, 这是系统文本协议(macOS NSTextInputClient 等)的要求, 和 Rust String 的字节偏移不是一回事. 实体内部按字节存文本时必须自己换算(见 10.3).

必须实现的方法:

方法说明

selected_text_range(ignore_disabled_input, window, cx) -> Option<UTF16Selection>当前选区; UTF16Selection { range, reversed } 的 reversed 表示光标在选区起始端

10.3 TextInput: 状态与 EntityInputHandler 实现

先看状态放哪. 示例的 TextInput 实体把文本、选区、IME 组合段、上一帧的排版结果都存下来:

#![allow(unused)]
fn main() {
struct TextInput {
    focus_handle: FocusHandle,          // 焦点句柄(见第 8 章)
    content: SharedString,              // 文本内容(UTF-8 字节)
    placeholder: SharedString,          // 空文本时的占位提示
    selected_range: Range<usize>,       // 选区(字节偏移); start == end 时光标
    selection_reversed: bool,           // 光标是否在选区的起始端
    marked_range: Option<Range<usize>>, // IME 组合段(字节偏移)
    last_layout: Option<ShapedLine>,    // 上一帧的排版结果, 换算坐标用
    last_bounds: Option<Bounds<Pixels>>, // 上一帧的元素边界
    is_selecting: bool,                 // 鼠标拖选中
}
}

UTF-16 换算是绕不开的一环: trait 传进来的是 UTF-16 偏移, 实体存的是字节偏移. 示例用 offset_to_utf16()/offset_from_utf16() 及其区间版互相转换, 例如取文本:

#![allow(unused)]
fn main() {
fn text_for_range(
    &mut self,
    range_utf16: Range<usize>,              // IME 给的是 UTF-16 范围
    actual_range: &mut Option<Range<usize>>, // 回填实际取到的范围
    _window: &mut Window,
    _cx: &mut Context<Self>,
) -> Option<String> {
    let range = self.range_from_utf16(&range_utf16); // 先换算成字节范围
    actual_range.replace(self.range_to_utf16(&range));
    Some(self.content[range].to_string())
}
}

插入/删除都走 replace_text_in_range(), 先定“替换谁“: 显式传的范围 → IME 组合段 → 当前选区:

#![allow(unused)]
fn main() {
fn replace_text_in_range(
    &mut self,
    range_utf16: Option<Range<usize>>,
    new_text: &str,
    window: &mut Window,
    cx: &mut Context<Self>,
) {
    let range = range_utf16
        .as_ref()
        .map(|range_utf16| self.range_from_utf16(range_utf16))
        .or(self.marked_range.clone())
        .unwrap_or(self.selected_range.clone());

    self.content =
        (self.content[0..range.start].to_owned() + new_text + &self.content[range.end..]).into();
    self.selected_range = range.start + new_text.len()..range.start + new_text.len();
    self.marked_range.take(); // 组合段一并清掉
    window.notify_text_input_changed(&self.focus_handle); // 同步给系统输入法
    cx.notify();
}
}

返回选区就是把 self.range_to_utf16(&self.selected_range) 和 selection_reversed 包成 UTF16Selection. 两个容易踩的细节: 光标移动按字素簇(grapheme)走(Backspace 要借 unicode-segmentation 的 grapheme_indices() 求前一个边界), 不然退格会把 emoji 或带音标的字符拆半; 删到开头无可删时响一声 window.play_system_bell().

10.4 自定义 Element 三阶段渲染

文本要精确控制排版和绘制, 光用 div() 不够, 需要实现 Element trait. 一帧内每个 Element 依次走三个阶段:

阶段方法职责
1. 布局请求request_layout()向 Taffy 布局系统要尺寸, 返回 (LayoutId, RequestLayoutState)
2. 绘制前prepaint()布局完成后拿到最终 bounds, 做坐标计算、准备绘制素材, 返回 PrepaintState
3. 绘制paint()把内容画到屏幕; 输入处理器也在这一步注册(见 10.6)

两个关联类型决定阶段之间传什么状态: RequestLayoutState 是 request_layout 产出、后两阶段读取的; PrepaintState 是 prepaint 产出、paint 读取的. 没有状态就用 ():

#![allow(unused)]
fn main() {
struct TextElement {
    input: Entity<TextInput>, // 实体句柄, 各阶段读写它的状态
}

impl Element for TextElement {
    type RequestLayoutState = ();
    type PrepaintState = PrepaintState; // 排版结果 + 光标/选区的绘制素材
    // request_layout/prepaint/paint 见 10.5
}
}

NOTE: 实现 Element 的同时还要实现 IntoElement(通常 type Element = Self, into_element() 返回 self), 这一步没有默认实现可省.

💡 提示: prepaint 常见的活儿是 window.insert_hitbox(bounds, ...) 登记命中区域; TextElement 不用插命中箱, 鼠标事件由外层 div() 的监听器处理(见 10.9).

10.5 TextElement 的三阶段实现

request_layout 只决定自己要多大: 宽度撑满父元素, 高度取一行行高.

#![allow(unused)]
fn main() {
fn request_layout(
    &mut self,
    _id: Option<&GlobalElementId>,
    _inspector_id: Option<&gpui::InspectorElementId>,
    window: &mut Window,
    cx: &mut App,
) -> (LayoutId, Self::RequestLayoutState) {
    let mut style = Style::default();
    style.size.width = relative(1.).into();          // 宽度撑满父元素: width: 100%
    style.size.height = window.line_height().into(); // 高度 = 一行行高
    (window.request_layout(style, [], cx), ())
}
}

prepaint 是重头戏: 算好“画什么“和“画在哪“, 存进 PrepaintState. 顺序是: 选显示文本(空则占位) → 构造 TextRun(IME 组合段加下划线) → shape_line() 排版 → 用排版结果算光标/选区矩形.

#![allow(unused)]
fn main() {
// 1. 空文本时画占位提示(淡色)
let (display_text, text_color) = if content.is_empty() {
    (input.placeholder.clone(), hsla(0., 0., 0., 0.2))
} else {
    (content, style.color)
};

// 2. IME 组合段拆成独立 TextRun 加下划线(表示"还没上屏"), 其余部分共用 run
let runs = if let Some(marked_range) = input.marked_range.as_ref() {
    vec![
        TextRun { len: marked_range.start, ..run.clone() },
        TextRun { len: marked_range.end - marked_range.start,
                  underline: Some(UnderlineStyle { color: Some(run.color), thickness: px(1.0), wavy: false }), ..run.clone() },
        TextRun { len: display_text.len() - marked_range.end, ..run },
    ]
    .into_iter().filter(|run| run.len > 0).collect()
} else {
    vec![run]
};

// 3. 排版成单行 ShapedLine, 后续坐标换算全靠它
let line = window.text_system().shape_line(display_text, font_size, &runs, None);

// 4. 无选区: 2px 宽的光标竖线: width: 2px; 有选区: 半透明矩形, 不画光标
let cursor_pos = line.x_for_index(cursor); // 字节偏移 → 行内 x 坐标
let (selection, cursor) = if selected_range.is_empty() {
    let cursor_bounds = Bounds::new(point(bounds.left() + cursor_pos, bounds.top()),
                                    size(px(2.), bounds.bottom() - bounds.top()));
    (None, Some(fill(cursor_bounds, gpui::blue())))
} else {
    // 选区起止的 x 坐标同样来自 line.x_for_index
    (Some(fill(Bounds::from_corners(/* 起点 */, /* 终点 */), rgba(0x3311ff30))), None)
};
}

paint 把准备好的素材兑现, 顺手注册输入处理器、缓存排版结果:

#![allow(unused)]
fn main() {
fn paint(/* ... */) {
    // 1. 注册本帧的输入处理器(见 10.6)
    let focus_handle = self.input.read(cx).focus_handle.clone();
    window.handle_input(&focus_handle, ElementInputHandler::new(bounds, self.input.clone()), cx);

    // 2. 画选区、文本、光标
    if let Some(selection) = prepaint.selection.take() {
        window.paint_quad(selection)
    }
    let line = prepaint.line.take().unwrap();
    line.paint(bounds.origin, window.line_height(), gpui::TextAlign::Left, None, window, cx).unwrap();
    if focus_handle.is_focused(window) && let Some(cursor) = prepaint.cursor.take() {
        window.paint_quad(cursor); // 只有聚焦时才画光标
    }

    // 3. 缓存排版结果和边界, 9.9 的坐标换算要用
    self.input.update(cx, |input, _cx| {
        input.last_layout = Some(line);
        input.last_bounds = Some(bounds);
    });
}
}

NOTE: 绘制文本没有 cx.paint_text(bounds, text, style) 这个方法 —— 先 window.text_system().shape_line(text, font_size, &runs, None) 排版成 ShapedLine, 再调它的 paint() 画出来. shape_line 只排单行, 文本带换行会触发断言.

10.6 注册输入处理器

EntityInputHandler 实现好之后不会自动生效, 要在每帧的 paint 阶段把实体包成 ElementInputHandler 交给窗口(上一节 paint 的第 1 步):

#![allow(unused)]
fn main() {
window.handle_input(
    &focus_handle, // 焦点句柄: 只有它持有焦点时处理器才生效
    ElementInputHandler::new(bounds, self.input.clone()), // 桥接 EntityInputHandler → InputHandler
    cx,
);
}
  • ElementInputHandler::new(element_bounds, entity) 两个参数: 元素在窗口中的边界(供 bounds_for_range 用)和实体句柄.
  • 注册只对当前这一帧有效, 下一帧要重新注册 —— 所以放在 paint() 里, 每帧都走.
  • 内部会检查 focus_handle.is_focused(): 没聚焦就什么都不注册.

实体自己改了文本或选区(而不是系统输入法改的), 要额外通知系统文本服务, 否则输入法内部状态会不同步:

方法何时调用
window.notify_text_input_changed(&focus_handle)文本内容变了(插入、删除后)
window.notify_text_selection_changed(&focus_handle)只是选区/光标移动了
window.request_virtual_keyboard()用户点击输入框时, 唤起被收起的软键盘

NOTE: 注册用的是 paint 阶段的 window.handle_input(...), 没有 register_input_handler() 这个方法, 也没有 cx.on_window_opened(... handle_input(cx.entity().downgrade())) 这种“窗口创建时注册一次“的写法.

10.7 焦点与光标

光标要不要画、输入要不要接, 全看焦点(焦点系统见第 8 章). TextInput 实现 Focusable 暴露 focus_handle, 渲染时用 .track_focus() 绑定:

#![allow(unused)]
fn main() {
// render() 里
div()
    .key_context("TextInput") // 动作派发的上下文名
    .track_focus(&self.focus_handle(cx)) // 绑定焦点句柄: 元素可聚焦
    .cursor(CursorStyle::IBeam) // 悬停时鼠标变工字形: cursor: text
}

示例启动后要主动聚焦一次(window.focus(&handle, cx)), 否则窗口打开时打不了字. 光标位置不是简单取 selected_range.start —— 反向选区(shift 向左选)时头在起始端, 用 selection_reversed 标记, cursor_offset() 据此返回 start 或 end.

移动光标(move_to)和扩展选区(select_to)是两个方法, 但都收束到同一套状态更新: 改 selected_range、window.notify_text_selection_changed() 通知系统、cx.notify() 重绘. Left/Right/Home/End 走 move_to, SelectLeft/SelectRight/SelectAll 走 select_to, 按键绑定和普通动作一模一样(见第 9 章).

💡 提示: 示例的光标不闪烁(blink), 聚焦时一直实心. 要闪烁效果, 用 cx.background_executor().timer(...) 定时翻转一个可见性标志再 cx.notify() 即可.

10.8 剪贴板操作

复制、剪切、粘贴自己写动作实现, 剪贴板读写在 App 上(Context 可解引用过去):

#![allow(unused)]
fn main() {
fn paste(&mut self, _: &Paste, window: &mut Window, cx: &mut Context<Self>) {
    if let Some(text) = cx.read_from_clipboard().and_then(|item| item.text()) {
        self.replace_text_in_range(None, &text.replace("\n", " "), window, cx);
    }
}

fn copy(&mut self, _: &Copy, _: &mut Window, cx: &mut Context<Self>) {
    if !self.selected_range.is_empty() {
        cx.write_to_clipboard(ClipboardItem::new_string(
            self.content[self.selected_range.clone()].to_string(),
        ));
    }
}
}
  • 读: cx.read_from_clipboard() -> Option<ClipboardItem>, 再 .text() -> Option<String> 取纯文本(剪贴板还可能有图片等其他类型).
  • 写: cx.write_to_clipboard(ClipboardItem::new_string(s)), 要构造 ClipboardItem.
  • cut 就是先 copy 再 replace_text_in_range(None, "", ...) 删掉选区; 快捷键用 KeyBinding::new("cmd-c", Copy, None) 这类绑定接到动作上.

💡 提示: 系统自己发起的粘贴(比如网页里的 paste 事件、移动端的粘贴菜单)不走上面的动作, 而是回调 EntityInputHandler::paste(item, ...), 默认实现就是取纯文本调 replace_text_in_range.

NOTE: 剪贴板 API 是 cx.read_from_clipboard()/cx.write_to_clipboard(ClipboardItem), 没有 cx.clipboard_read()/cx.clipboard_write("...") 这两个方法.

10.9 鼠标选择文本

鼠标交互三件事: 点击定位光标、拖拽扩展选区、shift 点击扩展选区. 先定状态转换:

#![allow(unused)]
fn main() {
fn on_mouse_down(&mut self, event: &MouseDownEvent, window: &mut Window, cx: &mut Context<Self>) {
    self.is_selecting = true;
    window.request_virtual_keyboard(); // 唤起软键盘(移动端)
    if event.modifiers.shift {
        self.select_to(self.index_for_mouse_position(event.position), window, cx); // 扩展选区
    } else {
        self.move_to(self.index_for_mouse_position(event.position), window, cx) // 定位光标
    }
}

fn on_mouse_move(&mut self, event: &MouseMoveEvent, window: &mut Window, cx: &mut Context<Self>) {
    if self.is_selecting {
        self.select_to(self.index_for_mouse_position(event.position), window, cx);
    }
}

fn on_mouse_up(&mut self, _: &MouseUpEvent, _window: &mut Window, _: &mut Context<Self>) {
    self.is_selecting = false;
}
}

三个回调都挂在外层 div() 上, 拖出元素外松开也要结束选择:

#![allow(unused)]
fn main() {
div()
    .on_mouse_down(MouseButton::Left, cx.listener(Self::on_mouse_down))
    .on_mouse_up(MouseButton::Left, cx.listener(Self::on_mouse_up))
    .on_mouse_up_out(MouseButton::Left, cx.listener(Self::on_mouse_up)) // 拖到元素外松开
    .on_mouse_move(cx.listener(Self::on_mouse_move))
}

坐标 → 文本下标的换算靠 paint 阶段缓存下来的 last_bounds 和 last_layout: x 找最近的字形位置, y 超出上/下边界就取首/尾:

#![allow(unused)]
fn main() {
fn index_for_mouse_position(&self, position: Point<Pixels>) -> usize {
    if self.content.is_empty() {
        return 0;
    }
    let (Some(bounds), Some(line)) = (self.last_bounds.as_ref(), self.last_layout.as_ref()) else {
        return 0;
    };
    if position.y < bounds.top() { return 0; }
    if position.y > bounds.bottom() { return self.content.len(); }
    line.closest_index_for_x(position.x - bounds.left()) // x 坐标 → 最近的字节偏移
}
}

NOTE: 点击定位没有 pixel_to_char_index() 这种现成方法 —— 示例用 ShapedLine::closest_index_for_x() 自己换算, 这也是 last_layout/last_bounds 存在的原因. 鼠标回调的签名是 (&mut self, &MouseDownEvent, &mut Window, &mut Context<Self>), 没有 ViewContext, 也不是直接收一个 Point<Pixels>.

11. 拖拽功能

拖拽(drag and drop)是列表、看板类界面的常见交互. GPUI的拖拽是声明式的: 源元素用 .on_drag() 说清「拖的是什么、拖起来长什么样」, 目标元素用 .on_drop() 决定「收不收、怎么处理」, 再用 .drag_over() 给悬停反馈. 拖拽数据可以是任意 'static 类型, 不需要实现特殊 trait.

11.1 拖拽源: .on_drag()

.on_drag() 把元素标记为可拖拽源, 一次收两个参数: 拖拽数据 value: T 和预览构造器 constructor. 按住左键移动超过 2 像素后拖拽自动开始, 构造器被调用一次, 返回一个实现 Render 的实体(Entity)作为跟随光标的拖拽预览:

#![allow(unused)]
fn main() {
let drag_info = DragInfo::new(ix, color); // 拖拽携带的数据, 普通结构体即可

div()
    .id(("item", ix)) // 每个可拖元素要先有唯一 id: on_drag 只在带 id 的元素上可用
    .size_32() // 32 号尺寸的正方形: width: 8rem; height: 8rem (128px)
    .cursor_move() // 拖动光标: cursor: move
    .child(format!("Item ({})", ix))
    .on_drag(drag_info, |info: &DragInfo, position, _, cx| {
        // 收 4 个参数: 拖拽数据、按下点相对元素原点的偏移、window、cx
        cx.new(|_| info.position(position)) // 构造预览实体, 跟随光标绘制
    })
}

源码里的完整签名(两部分都要给):

#![allow(unused)]
fn main() {
fn on_drag<T, W>(
    value: T,
    constructor: impl Fn(&T, Point<Pixels>, &mut Window, &mut App) -> Entity<W>,
) where
    T: 'static,
    W: 'static + Render;
}
  • T 是拖拽数据的类型, 任意 'static 类型都行; W 是预览实体的类型, 必须实现 Render.
  • on_drag 是带 id 元素(StatefulInteractiveElement)的方法, 元素上没写 .id() 就用不了.
  • 同一个元素只能调一次 on_drag, 重复调用在 debug 下直接断言失败.
  • 拖拽期间可用 cx.has_active_drag() 查询「现在有没有拖拽」.

11.2 放置目标: .on_drop()

.on_drop() 把元素标记为放置目标. 回调只在「拖拽数据的类型」和 on_drop::<T> 的 T 一致时才会触发, 类型匹配由GPUI按 TypeId 自动完成:

#![allow(unused)]
fn main() {
div()
    .id("drop-target")
    .w_128() // 宽: width: 32rem (512px)
    .h_32()  // 高: height: 8rem (128px)
    .on_drop(cx.listener(|this, info: &DragInfo, _, _| {
        // 回调直接拿到拖拽数据 &DragInfo
        this.drop_on = Some(*info); // 记录放进来的数据, 驱动边框/底色变化
    }))
    .child("Drop items here")
}
  • 回调收 (&T, &mut Window, &mut App); 用 cx.listener() 包一层(见 11.5)就能在回调里读写自己的状态.
  • on_drop/can_drop 是普通元素方法, 不要求 .id().

.can_drop() 给放置目标加一道谓词, 决定这个拖拽数据收不收:

#![allow(unused)]
fn main() {
div()
    .on_drop(cx.listener(|this, info: &DragInfo, _, _| {
        this.drop_on = Some(*info);
    }))
    .can_drop(|data, _window, _cx| {
        // 收 &dyn Any: 返回 false 时 on_drop 不触发, drag_over 样式也保持原样
        data.downcast_ref::<DragInfo>().is_some_and(|info| info.ix != 0)
    })
}

11.3 DragInfo: 拖拽数据载体

NOTE: GPUI没有 内置的 DragInfo 类型. 拖拽数据就是你在 .on_drag() 里传的那个 value, 什么结构体都行; 下面示例里的 DragInfo 是示例自己定义的(见 examples/drag_drop.rs), 一物两用: 既当拖拽数据, 又实现 Render 用作拖拽预览. 数据和预览也可以拆成两个类型, 只要预览那个实现 Render:

#![allow(unused)]
fn main() {
/// 拖拽数据: 记录拖的是第几项、什么颜色, 以及按下点的偏移
#[derive(Clone, Copy)]
struct DragInfo {
    ix: usize,
    color: Hsla,
    position: Point<Pixels>,
}

impl Render for DragInfo {
    fn render(&mut self, _: &mut Window, _: &mut Context<'_, Self>) -> impl IntoElement {
        div()
            .flex() // 弹性布局: display: flex
            .justify_center() // 主轴居中: justify-content: center
            .items_center() // 交叉轴居中: align-items: center
            .bg(self.color.opacity(0.5)) // 半透明项目色: background-color: rgb(.../50%)
            .text_color(gpui::white()) // 文字颜色: color: #ffffff
            .child(format!("Item {}", self.ix))
    }
}
}

预览实体由 .on_drag() 的构造器创建(cx.new(|_| ...))、由GPUI释放, 每次拖拽只创建一次; GPUI把它画在「鼠标位置 - 按下点偏移」处, 所以预览看起来停在当初抓取的位置.

11.4 drag_over 样式: 拖拽悬停时的视觉反馈

.drag_over::<S>() 在「类型为 S 的数据悬停在元素上」时追加一段样式, 挪走自动恢复. 闭包收「基础样式 + 拖拽数据 + window + cx」, 把改好的样式返回出去:

#![allow(unused)]
fn main() {
div()
    .id("drop-target")
    .on_drop(cx.listener(|this, info: &DragInfo, _, _| {
        this.drop_on = Some(*info);
    }))
    .drag_over::<DragInfo>(|style, _info, _window, _cx| {
        style
            .bg(gpui::blue().opacity(0.2)) // 悬停时淡蓝底: background-color: #0000ff33
            .border_2() // 边框加粗到 2px: border-width: 2px
            .border_color(gpui::blue()) // 边框颜色: border-color: #0000ff
    })
}

11.5 拖拽生命周期

一次完整拖拽经历的阶段:

  1. 开始拖拽: 在源元素上按住左键、移动超过 2 像素 → GPUI调用 .on_drag() 的构造器生成预览实体, 拖拽进入活跃状态(cx.has_active_drag() 变为 true).

  2. 拖拽移动: 鼠标移动 → 预览跟随光标, 窗口持续重绘; 需要在移动时做事(如调整滚动)就订阅 .on_drag_move::<T>():

    #![allow(unused)]
fn main() {
div()
    .on_drag_move::<DragInfo>(cx.listener(|this, e, _window, cx| {
        // e 是 DragMoveEvent<DragInfo>:
        //   e.event    鼠标移动事件(MouseMoveEvent)
        //   e.bounds   本元素的区域
        //   e.drag(cx) 取拖拽数据 &DragInfo
        this.hover_pos = Some(e.event.position); // 例如记录悬停位置
        cx.notify();
    }))
}

    该事件在拖拽期间的每次鼠标移动都会触发, 不管光标在不在元素内.

  3. 进入目标: 光标悬停到元素上且拖拽数据类型匹配 → .drag_over()/.group_drag_over() 样式生效(can_drop 谓词为 false 时保持原样).

  4. 离开目标: 光标挪走, 悬停样式自动失效, 元素恢复原样.

  5. 放置: 松开左键 → 命中元素的 on_drop 按类型匹配触发(先过 can_drop 谓词), 拖拽数据交给目标处理, 活跃拖拽随之结束.

  6. 取消: 松手时下方没有匹配的放置目标(或 can_drop 返回 false) → 活跃拖拽直接丢弃, 数据不给任何人; 也可以随时调 cx.stop_active_drag(window) 主动取消, 返回 bool 表示是否真有拖拽被取消.

NOTE: 按 Escape 取消拖拽 没有内置实现 —— 框架只在「松手落空/stop_active_drag」时清掉拖拽. 想要 Esc 取消, 自己绑一个动作(见第 8 章)在回调里调 cx.stop_active_drag(window).

💡 提示: 跨窗口与跨应用. 活跃拖拽存在 App 上, 同一应用的多个窗口都能命中放置目标. 拖出窗口时, 若源元素注册了 .external_drag_payload(), 拖拽会升级成平台原生拖拽(目前支持向外拖文件); 从系统拖文件进窗口则走 FileDropEvent 事件(Entered/Pending/Submit/Exited/Ended), 元素级钩子有 .on_file_drop_exit().

12. Entity 状态管理

GPUI 用实体(Entity)承载所有可变状态: 视图的字段、列表的数据、拖拽的载荷(见第 11 章)都住在实体里. 本章讲实体的创建、读写、通知、观察和所有权规则 —— 这是理解GPUI数据流的基础.

12.1 Entity: GPUI的核心状态容器

Entity<T> 是GPUI托管状态的类型安全句柄: 数据本体由GPUI统一持有, 你手里的句柄只负责引用它. 三个最基本的操作:

操作方法说明
创建cx.new(|cx| T { ... })构造 T 并返回 Entity<T>
读取entity.read(cx)不可变借用, 拿到 &T
更新entity.update(cx, |data, cx| ...)可变借用, 拿到 &mut T 和这个实体的 Context<T>

纯数据结构体、自定义视图(实现 Render, 见第 2 章)都可以做成实体, 区别只是视图会被窗口渲染出来.

12.2 创建和更新 Entity

#![allow(unused)]
fn main() {
pub struct Counter {
    pub count: i32,
}

// 创建: 闭包返回初始状态, cx.new 返回句柄
let counter: Entity<Counter> = cx.new(|_cx| Counter { count: 0 });

// 读取: read 从&App借用, 返回 &Counter
let current = counter.read(cx).count;

// 更新: 闭包拿到 &mut Counter 和该实体的 Context<T>
counter.update(cx, |counter, cx| {
    counter.count += 1;
    cx.notify(); // 状态变了要通知, 否则界面不动(见 12.4)
});
}

Entity 上与读写相关的方法:

方法说明
entity.read(cx)不可变借用 &T,cx收 &App
entity.read_with(cx, f)不可变借用, 并套一层闭包: f(&T, &App) -> R
entity.update(cx, f)可变借用, 并套一层闭包: f(&mut T, &mut Context<T>) -> R
entity.update_in(cx, f)同上, 闭包多收一个 &mut Window(窗口上下文)
entity.write(cx, value)整体替换值, 并自动 notify
cx.reserve_entity() + cx.insert_entity()先占位拿句柄/实体 id, 稍后再填内容(构建互相引用时用)

NOTE: 创建实体用 cx.new(...), 生产代码里没有 cx.new_entity() 这个方法(只在测试专用的 TestAppContext 上有). new 是 AppContext trait 的方法, App、Context<T>、AsyncApp 上都能调 —— 也就是说可以在一个实体的构造闭包里直接创建另一个实体.

12.3 cx.observe(): 观察状态变化

cx.observe() 订阅另一个实体的「状态变了」通知: 只要被观察的实体调了 cx.notify(), 回调就会被触发. 回调收三个参数: 观察者自己的状态、被观察实体的句柄、观察者的 Context:

#![allow(unused)]
fn main() {
pub struct Parent {
    child: Entity<Child>,
    child_data: String,
}

impl Parent {
    fn new(child: Entity<Child>, cx: &mut Context<Self>) -> Self {
        cx.observe(&child, |parent, child_entity, cx| {
            // 被观察的 child 一调 notify 就会进到这里
            parent.child_data = child_entity.read(cx).value.clone(); // 同步它的数据
            cx.notify(); // 自己也变了, 通知重绘
        })
        .detach(); // 或存进字段, 见下文

        Parent { child, child_data: String::new() }
    }
}
}

observe 返回 Subscription: 它被丢弃时订阅就取消, 所以要么 .detach()(一直有效, 直到被观察实体释放), 要么存进实体字段里续命:

#![allow(unused)]
fn main() {
// 存字段: 订阅活多久由实体决定
_todos_subscription: cx.observe(todos, |_, _, cx| cx.notify()),
}

同族方法还有 cx.observe_self()(观察自己)和 cx.observe_release()(实体被释放时收尸).

💡 提示: 想发「带数据的事件」而不只是「状态变了」, 用 EventEmitter + cx.subscribe()/cx.emit(): 被观察方 cx.emit(事件), 订阅方收到 (&mut 自己, 发送者句柄, &事件, cx). examples/ownership_post.rs 里两个都有.

12.4 cx.notify(): 通知重新渲染

cx.notify() 告诉 GPUI「这个实体的状态变了」, 引发一串连锁反应:

  • 注册在它身上的观察者(cx.observe 等)被触发, 由观察者决定要不要同步/再 notify;
  • 引用它的视图被标记为待重绘, 窗口在下一帧重新构建受影响的元素树.

NOTE: entity.update(cx, ...) 改字段不会自动重绘 —— 忘了调 cx.notify() 界面就不会变, 这是最常见的新手坑. 个别鼠标回调(如 on_drop)看起来“没 notify 也刷新了“, 那是事件派发顺带触发的刷新, 别依赖这种巧合.

12.5 cx.listener(): 类型安全的回调

GPUI 事件回调的标准形状是 Fn(&E, &mut Window, &mut App), 里面摸不到自己的状态. cx.listener() 把它补成「先借出自己实体的状态再执行」的闭包, 闭包收四个参数: 自己的状态、事件、window、自己的 Context:

#![allow(unused)]
fn main() {
div()
    .px_4() // 内边距: padding: 0 1rem
    .py_2() // 内边距: padding: 0.5rem 0
    .bg(rgb(0x4040ff)) // 背景色: background-color: #4040ff
    .rounded_md() // 圆角: border-radius: 6px
    .child("Move me to a new window")
    .on_mouse_down(
        MouseButton::Left,
        cx.listener(|_this, _, _window, cx| {
            // 第一个参数是 &mut HelloWorld, 可以随便读写自己的字段
            cx.emit(MoveToNewWindow); // 在自己的上下文里发事件
        }),
    )
}

返回值正好是事件回调的形状, 所以能直接递给 on_click、on_drop、on_mouse_down 等一切元素方法.

NOTE: listener 闭包收四个参数(this、事件、window、cx), 没有 |view, event, cx| 三参数写法 —— 那是旧版GPUI的签名, 现在编译不过. 回调里也要改状态别忘了 cx.notify().

12.6 所有权模型

GPUI 基于 Rust 所有权设计了自己的托管方式:

  • 数据本体唯一: T 的所有权在GPUI的实体表里, 谁都不能直接搬走;
  • entity.clone() 克隆的是句柄, 只加引用计数, 不复制数据(类似 Rc);
  • 读写经由句柄: read 拿 &T(可多个并存), update 拿 &mut T + Context<T>(独占);
  • 冲突是运行时检查的: 同一实体的 update 未结束就再 read/update 会 panic(双租约), 并打出调试位置.
#![allow(unused)]
fn main() {
let entity1 = cx.new(|_| MyData { value: 42 });
let entity2 = entity1.clone(); // 克隆句柄, 数据只有一份

entity2.update(cx, |data, cx| {
    data.value = 100; // entity1 和 entity2 指向同一份数据
    cx.notify();
});

assert_eq!(entity1.read(cx).value, 100); // 两个句柄看到同一份数据
}

NOTE: “借用冲突编译期就能抓到、不会运行时 panic” 这个说法不成立. 闭包内的 &T/&mut T 当然受编译器保护, 但跨句柄的读写冲突是GPUI运行时租约检查的, 嵌套借用同一实体照样 panic. 真正的线程安全另有一套: 读写都收敛到主线程, 异步任务经 AsyncApp 回来更新(见 12.7).

12.7 弱引用 WeakEntity

WeakEntity<T> 是不阻止实体释放的弱句柄, 用来打破「订阅/异步任务 ↔ 实体」之间的引用循环. entity.downgrade() 得到弱引用, cx.weak_entity() 拿自己实体的弱引用(如 Context::spawn 的异步闭包里收到的就是它):

#![allow(unused)]
fn main() {
// 降级成弱引用: 不增加强引用计数, 不阻止实体被释放
let weak: WeakEntity<Counter> = entity.downgrade();

// 使用前升级: 实体可能已经没了, 所以返回 Option
if let Some(entity) = weak.upgrade() {
    entity.update(cx, |data, cx| {
        data.count += 1;
        cx.notify();
    });
}

// 一步到位的弱引用更新: 实体已释放时返回 Err 而不是 panic
weak.update(cx, |data, cx| {
    data.count += 1;
    cx.notify();
})?;
}
方法说明
entity.downgrade()强句柄降级为 WeakEntity<T>
weak.upgrade()升回 Entity<T>, 实体已释放则 None
weak.update(cx, f)/weak.read_with(cx, f)弱引用版读写, 返回 Result
weak.is_upgradable()实体是否还活着
WeakEntity::new_invalid()永远升不了级的占位弱引用

NOTE: upgrade() 没有 cx 参数, 直接返回 Option<Entity<T>>; 检查存活用 is_upgradable(), 没有 weak.is_valid(cx) 这个方法.

NOTE: 什么时候用弱引用: 订阅回调、长期存活的异步任务、互相引用的父子实体. 反过来, 短命闭包里直接 clone() 强句柄就好.

13. 事件发布订阅

第 7 章讲的是 UI 事件(点击、鼠标、悬停): 由用户操作触发, GPUI按元素层级分发. 本章讲的是实体(Entity)之间的自定义事件: 一个实体定义并发射事件, 其他实体订阅后做出反应, 用来解耦业务逻辑层的通信.

13.1 EventEmitter trait: 事件发射器

事件本身只是普通的 'static 类型(枚举或结构体都行), 什么都不用实现. 要发射事件的实体结构体实现 EventEmitter<事件类型> 这个标记 trait, 声明“我能发这种事件“:

#![allow(unused)]
fn main() {
use gpui::*;

/// 事件载荷: 结构体或枚举都可以
struct Change {
    increment: usize,
}

struct Counter {
    count: usize,
}

/// EventEmitter 是空的标记 trait:
/// 只声明 Counter 可以发射 Change 事件, 没有方法要实现
impl EventEmitter<Change> for Counter {}
}

一个实体可以发多种事件: 给每个事件类型写一个 impl 就行, 订阅方按事件类型分别订阅.

NOTE: 本仓库使用的GPUI里 EventEmitter 是手写的空实现, 没有 #[derive(EventEmitter)] 这个派生宏, 也不是“在事件枚举上派生“ —— 实现写在发射方实体上, 事件类型自己不碰任何 trait.

13.2 cx.emit(): 发射事件

cx.emit() 只存在于实体自己的 Context<T> 上(要求 T: EventEmitter<Evt>), 通常写在实体的更新方法里, 和 cx.notify() 搭配:

#![allow(unused)]
fn main() {
impl Counter {
    fn increment(&mut self, delta: usize, cx: &mut Context<Self>) {
        self.count += delta;
        cx.notify(); // 通知 GPUI: 状态变了, 需要重新渲染
        cx.emit(Change { increment: delta }); // 发射事件, 通知所有订阅者
    }
}
}

也可以在 entity.update(...) 的闭包里直接发(完整示例 ownership_post.rs 的写法):

#![allow(unused)]
fn main() {
counter.update(cx, |counter, cx| {
    counter.count += 2;
    cx.notify();
    cx.emit(Change { increment: 2 });
});
}

emit() 并不是“调用那一行立刻执行所有回调“, 而是把事件排进 effect 队列, 本轮 update 结束时统一派发(见 13.5). 所以在同一个闭包里 emit() 之后马上读订阅者状态, 可能还没更新.

13.3 cx.subscribe(): 订阅事件

cx.subscribe() 在订阅者的 Context<T> 上调用, 收一个发射者句柄和回调, 返回 Subscription. 回调是四个参数 (订阅者, 发射者句柄, &事件, cx):

方法定义处回调形状
cx.subscribe(&entity, h)Context<T>(|this, emitter, event, cx| ...)
cx.subscribe_self(h)Context<T>(|this, event, cx| ...) 订阅自己
cx.subscribe_in(&entity, window, h)Context<T>(|this, emitter, event, window, cx| ...) 回调里多拿一个 Window
cx.subscribe(&entity, h)App(|emitter, event, cx| ...) 不绑定订阅者实体
 
#![allow(unused)]
fn main() {
// 创建另一个实体, 在构造中订阅 counter 的事件(取自 ownership_post.rs)
let subscriber = cx.new(|cx: &mut Context<Counter>| {
    cx.subscribe(&counter, |subscriber, _emitter, event, _cx| {
        subscriber.count += event.increment * 2; // 收到事件后改自己的状态
    })
    .detach(); // 不持有订阅句柄: 订阅一直有效, 直到 counter 被释放

    Counter {
        count: counter.read(cx).count * 2,
    }
});
}

Subscription 要保存住或 .detach(), 否则订阅立刻失效: 它标了 #[must_use], Drop 时自动退订. 两种存法:

  • 存进结构体字段(常用 _subscription: Subscription): 组件释放时自动退订, 生命周期跟订阅者走.
  • .detach(): 脱离句柄, 订阅持续到被订阅的实体释放为止, 适合“监听一次就不管了“.

Subscription::join(a, b) 把两个订阅合成一个, 一起保存或一起 detach.

订阅自己的事件用 subscribe_self, 回调少一个发射者参数(发射者就是自己):

#![allow(unused)]
fn main() {
cx.subscribe_self(|this, event: &Change, _cx| {
    this.count += event.increment; // 自己 emit 的事件自己也能收到
});
}

💡 提示: 回调收的事件是 &Evt 借用(枚举要用 *id 这类方式取值拷出来), 第二个参数是发射者的 Entity<T2> 句柄, 用它能反查发射者状态.

13.4 多级事件传播(父子实体之间的事件流)

NOTE: GPUI的实体事件没有 DOM 那样的父子冒泡 —— 事件只发给“订阅了该实体“的监听器, 不会自动沿实体层级向上传播. 所谓“多级传播“, 是指逐级订阅、逐级转发:

#![allow(unused)]
fn main() {
// 中间层: 订阅底层实体, 加工后转发自己的事件
struct Tally {
    total: usize,
}
struct Tallied {
    total: usize,
}
impl EventEmitter<Tallied> for Tally {}

impl Tally {
    fn bind(&mut self, counter: &Entity<Counter>, cx: &mut Context<Self>) {
        // 第一跳: Tally 订阅 Counter
        cx.subscribe(counter, |this, _emitter, event, cx| {
            this.total += event.increment;
            // 第二跳: 再用自己的事件发给订阅了 Tally 的上层
            cx.emit(Tallied { total: tally.total });
        })
        .detach();
    }
}
}

顶层只要订阅 Tally 就能拿到加工后的结果, 不必知道 Counter 的存在 —— 这正是事件解耦的意义. 如果中间层不需要加工/过滤, 让顶层直接订阅底层实体即可, 省掉转发.

13.5 事件生命周期

一次完整的事件流走这几步:

  1. 定义: 事件是普通类型; 在发射方实体上写 impl EventEmitter<事件>.
  2. 发射: cx.emit() 把事件排进 effect 队列, 不立刻回调.
  3. 派发: 本轮 update 结束时, GPUI统一 flush effect, 按入队顺序把每个事件发给该实体的所有订阅者.
  4. 处理: 订阅回调里改自己的状态, 通常再调 cx.notify() 触发重新渲染.
  5. 清理: Subscription 被 Drop(或组件释放)即退订; 发射实体被释放时, 挂在它身上的监听器一并移除.

NOTE: 事件是延迟派发的 —— emit() 那一刻订阅者收不到, 要等本轮 update 结束. 在 counter.update(cx, ...) 返回后再读订阅者, 才能看到事件处理完的最新状态.

#![allow(unused)]
fn main() {
counter.update(cx, |counter, cx| {
    counter.count += 2;
    cx.emit(Change { increment: 2 });
});
// update 返回时 effect 已经 flush 完, 订阅者状态是新的(ownership_post.rs 的断言)
assert_eq!(subscriber.read(cx).count, 4);
}

💡 提示: EventEmitter 事件与 UI 事件的区别 —— UI 事件(on_click 等)由用户操作触发、GPUI 分发; EventEmitter 事件由业务代码自己定义和发射. 典型组合: 在 on_click 回调里调 cx.emit(), 把 UI 事件转成业务事件再广播给其他实体.

14. 全局状态

有些数据(主题、排版参数、用户偏好)不属于任何单个组件, 而是整个应用共享一份. GPUI用 Global trait + App 上的全局存储实现这种单例状态: 每个类型只有一份, 任何地方都能读写, 还能订阅它的变化.

14.1 Global trait: 跨组件共享状态

Global 是一个空的标记trait, 只声明“这个类型可以作为全局状态存进 App“, 没有任何方法要实现 —— 所以实现体就是空的:

#![allow(unused)]
fn main() {
use gpui::*;

pub struct MySettings {
    pub theme: String,
    pub font_size: f32,
}

/// 空实现, 只为满足 Global trait 的标记:
/// 声明这个类型可以作为全局状态存进 App
impl Global for MySettings {}
}

全局存储按类型去重: 一个类型全局只有一份, cx.set_global() 再调一次就是整体替换. 想要“多个同类型实例“, 用 newtype 包一层(见 14.4), 或者干脆改用 Entity.

14.2 App/Context 上的全局状态访问方法

App/Context 上的全局状态访问方法:

方法说明

cx.global::<G>()只读引用, 未初始化会 panic
cx.try_global::<G>()只读, 返回 Option<&G>, 不会 panic
cx.has_global::<G>()是否已初始化(返回 bool)
cx.global_mut::<G>()可变引用, 未初始化会 panic
cx.default_global::<G>()可变引用, 没有就用 Default 先创建

#![allow(unused)]
fn main() {
// 启动时注册全局状态(没有就创建, 有就整体替换)
cx.set_global(MySettings {
    theme: "dark".into(),
    font_size: 14.0,
});

// 任意组件里读取(未初始化会 panic, 所以要先 set_global)
let settings = cx.global::<MySettings>();

if let Some(settings) = cx.try_global::<MySettings>() {
    let _ = &settings.theme;
}

// 更新: 闭包拿到 &mut 全局值和上下文
cx.update_global(|settings: &mut MySettings, _cx| {
    settings.theme = "high_contrast".into();
});
}

NOTE: turbofish 的正确写法是 cx.global::<G>()/cx.observe_global::<G>(...). 另外 set_global、global_mut、update_global、default_global、remove_global 改完(或访问完)都会触发全局观察者(见 14.3), update_global 即使闭包里什么都没改也会触发.

14.3 cx.observe_global(): 观察全局状态变化

cx.observe_global::<G>() 订阅某个全局类型的变化, 返回 Subscription(保存或 .detach() 的规则和第 12 章一样). 实体上和 App 上的回调形状不同:

方法回调形状
cx.observe_global::<G>(h) (Context<T>)(|this, cx| ...) 拿到订阅者自身
cx.observe_global::<G>(h) (App)(|cx| ...) 不绑定订阅者
 
#![allow(unused)]
fn main() {
pub struct ThemeAware {
    current_theme: String,
    // 订阅存进字段: 组件释放时自动退订
    _global_subscription: Subscription,
}

impl ThemeAware {
    fn new(cx: &mut Context<Self>) -> Self {
        let subscription = cx.observe_global::<MySettings>(|this, cx| {
            // 任何地方 set_global/update_global 修改 MySettings 后触发
            this.current_theme = cx.global::<MySettings>().theme.clone();
            cx.notify(); // 通知 GPUI: 状态变了, 需要重新渲染
        });

        ThemeAware {
            current_theme: cx.global::<MySettings>().theme.clone(),
            _global_subscription: subscription,
        }
    }
}
}

和事件一样, 观察者回调是延迟派发的: 修改全局状态只是把通知排进 effect 队列, 本轮 update 结束时才统一触发.

14.4 实战: text.rs 里的字体全局状态管理

本仓库的 examples/text.rs 用全局状态管理整套排版参数(字号、行高、字号阶梯), 是 Global 的经典用法. 关键片段:

#![allow(unused)]
fn main() {
/// 一组全局排版参数
#[derive(Clone, Debug)]
pub struct TextContext {
    /// 基础字号(像素). 对应 font-size: 16px
    font_size: f32,
    /// 行高倍数. 对应 line-height: 1.3(无单位, 表示字号的倍数)
    line_height: f32,
    /// 字号阶梯比例, 每升一级字号就乘以它
    type_scale: f32,
}

/// 把 TextContext 包一层, 好注册成GPUI的全局状态(Global).
/// Arc 让多处共享同一份设置, 不用反复克隆.
#[derive(Clone, Debug)]
pub struct GlobalTextContext(pub Arc<TextContext>);

/// 空实现, 只为满足 Global trait 的标记: 声明这个类型可以作为全局状态存进 App
impl Global for GlobalTextContext {}
}

启动时注册, 任意组件里读取:

#![allow(unused)]
fn main() {
// 启动时: 把排版设置注册成全局状态, 供所有组件读取
cx.set_global(GlobalTextContext(Arc::new(TextContext::default())));

// 读取: text.rs 还给 GlobalTextContext 实现了 Deref,
// 所以能直接 .font_size 取字段, 不用写 .0.font_size
let font_size = cx.global::<GlobalTextContext>().font_size;
}

text.rs 里还包了一个便捷 trait, 让 App 能直接写 cx.text_context():

#![allow(unused)]
fn main() {
pub trait ActiveTextContext {
    fn text_context(&self) -> &Arc<TextContext>;
}

impl ActiveTextContext for App {
    fn text_context(&self) -> &Arc<TextContext> {
        &self.global::<GlobalTextContext>().0
    }
}
}

14.5 全局状态 vs Entity 的选择

选择原则: 优先用 Entity, 只有“确实全应用只有一份、且不挂靠任何组件“的数据才用 Global. 全局状态的滥用风险:

  • 紧耦合: 任何地方都能 cx.global() 直读, 组件之间形成隐式依赖, 可维护性下降.
  • 测试困难: 单测之间共享同一份全局值, 需要额外的设置/清理.
  • 一类型一实例: 多个模块想各存一份同类型数据就会互相覆盖, 要么 newtype 包装, 要么改用 Entity.

15. 列表与虚拟化

数据量大的列表如果一次性渲染所有行, 滚动会严重卡顿. GPUI提供 uniform_list(等高行)和 list(变高行)两种虚拟化列表, 只渲染可见区域的行, 十万行也能流畅滚动.

💡 提示: 虚拟化把渲染复杂度从 O(n) 降到 O(k), k 是可见行数(通常不超过 50). 10 万行数据里, 任何一帧真正创建的元素只有几十个.

15.1 uniform_list: 等高行虚拟列表

uniform_list 适用于所有行高度相同的场景(文件列表、消息列表、数据表格). 它不走完整的 taffy 布局, 而是量出第一行的高度, 其余行按这个高度依次排列, 因此比 list 快得多:

#![allow(unused)]
fn main() {
use gpui::*;

struct UniformListExample {}

impl Render for UniformListExample {
    fn render(&mut self, _window: &mut Window, cx: &mut Context<Self>) -> impl IntoElement {
        div().size_full().bg(rgb(0xffffff)).child(
            uniform_list(
                "entries", // 列表 id,GPUI内部跟踪滚动状态用
                50,       // 行数, 可以是十万行
                cx.processor(|_this, range, _window, _cx| {
                    // 回调只收到可见区间的行号, 比如 12..24
                    let mut items = Vec::new();
                    for ix in range {
                        let item = ix + 1;

                        items.push(
                            div()
                                .id(ix)          // 每行要有 id, 才能响应点击等交互
                                .px_2()          // 左右内边距: padding-left: 0.5rem; padding-right: 0.5rem
                                .cursor_pointer() // 悬停显示手型: cursor: pointer
                                .on_click(move |_event, _window, _cx| {
                                    println!("clicked Item {item:?}");
                                })
                                .child(format!("Item {item}")),
                        );
                    }
                    items // 返回这个区间的所有行, 元素类型: Vec<R: IntoElement>
                }),
            )
            .h_full(), // 列表高度撑满父容器: height: 100%
        )
    }
}
}

uniform_list 的签名: uniform_list(id, item_count, f), 其中 f: Fn(Range<usize>, &mut Window, &mut App) -> Vec<R>.

滚动状态 UniformListScrollHandle: 要读写滚动位置(滚动条、“跳到底部”), 在视图里存一个句柄并绑上去:

#![allow(unused)]
fn main() {
scroll_handle: UniformListScrollHandle, // 滚动句柄: 记录/控制列表的滚动位置

// 渲染时绑定
uniform_list("items", count, cx.processor(...))
    .track_scroll(&self.scroll_handle) // 绑定句柄, 之后可以 scroll_to_item/scroll_to_bottom
}

句柄常用方法: scroll_to_item(ix, ScrollStrategy::Top/Center/Bottom/Nearest)(把某行滚进视野)、scroll_to_bottom()、logical_scroll_top_index()(当前第一可见行号).

cx.processor() 回调生成列表项: cx.processor(|this, range, window, cx| ...) 把「带视图状态的闭包」变成 uniform_list 需要的回调: 闭包第一个参数 this 就是 &mut self, 可以读写视图字段(比如顺手记下 this.visible_range). 不需要状态时, 直接传普通闭包也行.

滚动优化原理: 渲染每一帧时, uniform_list 根据滚动偏移算出可见行号区间, 回调只为这个区间创建元素; 滚出视野的行直接丢弃, 滚进来的新行按同一模板重建. 由于所有行等高, 行高 × 行号就是行的位置, 不需要逐行测量.

NOTE: 这版GPUI没有 UniformListState 这个类型, 也不接收行高参数(如 UniformListState::new(cx.entity(), 40.0)) —— 行高由第一个元素的测量结果决定, 滚动状态用 UniformListScrollHandle(可选, 见上).

15.2 list: 变高行列表

行高不一致时(聊天消息、评论列表)用 list. 它通过 ListState 管理, 每行渲染出来后动态测量实际高度:

#![allow(unused)]
fn main() {
use gpui::{ListAlignment, ListState, ...};

const ITEM_COUNT: usize = 40;

struct BottomListDemo {
    list_state: ListState, // 变高行列表的滚动/测量状态, 存在视图里
}

impl BottomListDemo {
    fn new() -> Self {
        Self {
            // 参数: 行数 40, 底部对齐, overdraw 500px(视口外多渲染的余量, 防止滚动露白)
            list_state: ListState::new(ITEM_COUNT, ListAlignment::Bottom, px(500.)).measure_all(),
        }
    }
}
}

#![allow(unused)]
fn main() {
list(self.list_state.clone(), |index, _window, _cx| {

        .h(height)                // 行高: height: 30px ~ 70px
        .w_full()                 // 宽度撑满: width: 100%
        .flex()                   // 弹性布局: display: flex
        .items_center()           // 垂直居中: align-items: center
        .px_3()                   // 左右内边距: padding-left: 0.75rem; padding-right: 0.75rem
        .border_b_1()             // 底部 1px 边框: border-bottom-width: 1px
        .border_color(rgb(0xEEEEEE)) // 边框颜色: border-color: #eeeeee
        .child(format!("Item {index}"))
        .into_any() // list 要求每行返回 AnyElement
})
.flex_1() // 列表占满剩余高度: flex: 1 1 0%
}

ListState 的创建与测量:

方法说明

.measure_all()首帧测量所有行, 滚动条尺寸才准(大列表首帧会慢)

15.3 自定义滚动条

列表自带滚动, 但滚动条外观可以自己画. ListState 有一组滚动条辅助方法, 直接给出定位滑块所需的全部数据(取自 list_example):

#![allow(unused)]
fn main() {
let max_offset = self.list_state.max_offset_for_scrollbar().y; // 可滚动的最大偏移
let current_offset = -self.list_state.scroll_px_offset_for_scrollbar().y; // 当前滚动偏移
let viewport_height = self.list_state.viewport_bounds().size.height; // 视口高度

let raw_fraction = if max_offset > px(0.) {
    current_offset/max_offset // 滚动比例: 0.0 ~ 1.0
} else {
    0.
};
}

有了比例, 轨道 + 滑块就是两个普通 div: 滑块高度 = 视口高度 × 视口占内容的比例(至少 30px), 滑块顶距 = (轨道高 − 滑块高) × 比例.

要支持拖拽滑块, 参考 data_table 示例的做法: 用 canvas() 在绘制阶段挂鼠标事件, 拖动时改写滚动句柄的偏移:

#![allow(unused)]
fn main() {
canvas(
    |_, _, _| (), // prepaint 闭包: 布局阶段的准备工作, 这里不需要
    move |thumb_bounds, _, window, _| {
        // paint 闭包: 拿到滑块的 bounds, 在这里注册鼠标事件
        window.on_mouse_event(move |ev: &MouseDownEvent, _, _, cx| { /* 记下拖拽起点 */ });
        window.on_mouse_event(move |_: &MouseUpEvent, _, _, cx| { /* 清掉拖拽状态 */ });
        window.on_mouse_event(move |ev: &MouseMoveEvent, _, _, cx| {
            if !ev.dragging() {
                return; // 没在拖拽就不处理
            }
            // 按拖拽位置换算滚动偏移, 写回句柄
            scroll_handle.set_offset(point(px(0.), -offset_y));
        })
    },
)
.size_full(), // 画布铺满滑块: width: 100%; height: 100%
}

NOTE: canvas() 收两个闭包(prepaint, paint), 单闭包的 canvas(move |bounds, _, cx| ...) 配 cx.paint_quad(...) 这种写法 没有 —— 画矩形是先用 quad(bounds, 圆角, 背景, 边框宽, 边框色, 边框样式) 构造 PaintQuad, 再 window.paint_quad(...) 绘制. 不需要自绘时, 像 list_example 那样用两个 div 拼滚动条更简单.

15.4 data_table: 大数据表格

data_table 示例是 uniform_list 的实战: 一万行行情数据 + 自绘滚动条. 两个关键技巧:

Rc 共享数据避免克隆: 大数据集用 Rc 让所有行引用同一份数据, 每行只克隆引用计数:

#![allow(unused)]
fn main() {
use std::rc::Rc;

struct DataTable {
    /// 用 Rc 共享同一份行情数据, 避免每行克隆整个结构
    quotes: Vec<Rc<Quote>>,
    scroll_handle: UniformListScrollHandle, // 滚动句柄: 自绘滚动条靠它读写位置
}
}

RenderOnce 实现 TableRow: 行元素只需要渲染一次(数据不可变), 实现 RenderOnce(消费 self)比持有状态的 Render(&mut self)更轻:

#![allow(unused)]
fn main() {
#[derive(IntoElement)] // 派生 IntoElement, TableRow 可以直接当元素塞进列表
struct TableRow {
    ix: usize,
    quote: Rc<Quote>, // 只持有 Rc 引用, 不拥有数据
}

impl RenderOnce for TableRow {
    fn render(self, _window: &mut Window, _cx: &mut App) -> impl IntoElement {
        let color = self.quote.change_color();
        div()
            .flex()                    // 弹性布局: display: flex
            .flex_row()                // 横向排列: flex-direction: row
            .border_b_1()              // 底部 1px 边框: border-bottom-width: 1px
            .border_color(rgb(0xE0E0E0)) // 边框颜色: border-color: #e0e0e0
            .bg(if self.ix.is_multiple_of(2) {
                rgb(0xFFFFFF) // 斑马纹偶数行: background-color: #ffffff
            } else {
                rgb(0xFAFAFA) // 斑马纹奇数行: background-color: #fafafa
            })
            .py_0p5() // 上下内边距: padding-top: 0.125rem; padding-bottom: 0.125rem
            .px_2()   // 左右内边距: padding-left: 0.5rem; padding-right: 0.5rem
            .children(FIELDS.map(|(key, width)| self.render_cell(key, px(width), color)))
    }
}
}

表格体就是 14.1 的 uniform_list, 只是每行换成 TableRow::new(i, quote.clone())(克隆的是 Rc, 不是数据):

#![allow(unused)]
fn main() {

.size_full()               // 铺满容器: width: 100%; height: 100%
.track_scroll(&self.scroll_handle), // 绑定滚动句柄, 自绘滚动条用它读写偏移
}

16. 浮层 Popover

下拉菜单、悬浮提示、选择器这类“浮在正文之上“的内容都属于 Popover.

GPUI的浮层由两个核心 API 搭配而成:

  • deferred() 把内容抬到独立的绘制层.
  • anchored() 负责把内容锚定到触发元素的某个角上.

16.1 deferred(): 延迟渲染容器

deferred() 的语义是布局留在原地、绘制推迟到所有祖先之后: 子元素照常参与当前元素树的布局, 但绘制被挪到整个界面画完之后, 所以浮层永远盖在正文上, 不会被后渲染的内容盖住.

#![allow(unused)]
fn main() {
deferred(
    anchored() // 浮层锚定
        .anchor(Anchor::TopLeft) // 浮层锚定定位: 浮层挂在触发元素的左上角
        .snap_to_window_with_margin(px(8.)) // 贴边收回时留 8px 余量, 保证浮层不出窗口
        .child(popover()), // 浮层内容
)
.priority(1), // 浮层绘制优先级: 数字大的画在上层
}

deferred() 常用配置:

方法说明
deferred(child)把 child 变成浮层(延迟绘制)
.priority(n)多个浮层之间的堆叠顺序, 大的在上(默认 0)
.with_priority(n)与 .priority(n) 完全等价

NOTE: deferred() 没有“条件渲染“参数, 显隐要自己控制, 常用 .when(self.open, |this| this.child(deferred(...))): 状态开着才把浮层挂进元素树. NOTE: 优先级是链式方法 .priority(1)(或 .with_priority(1)), 没有 with_priority(1).child(...) 这个自由函数.

16.2 anchored(): 锚定定位(Anchor 枚举)

anchored() 把浮层钉在父元素包围盒的参考点上, 下拉菜单通常锚定在按钮下方. Anchor 有 8 个变体, 覆盖四角、上下边中点、左右边中点:

变体参考点典型用途
Anchor::TopLeft/TopCenter/TopRight上边(左/中/右)悬浮提示
Anchor::BottomLeft/BottomCenter/BottomRight下边(左/中/右)下拉菜单(常用 BottomLeft)
Anchor::LeftCenter/RightCenter左右边中点级联子菜单

GPUI 的 Anchor 枚举(如 TopLeft、BottomLeft 等)是以弹窗(Popover)自身的对齐边角为基准来定义的, 而不是以触发器为基准.

  • Top* 系列(如 TopLeft)：将弹窗自身的顶部贴住触发器底部, 因此弹窗会向下展开显示在下方.

  • Bottom* 系列(如 BottomLeft)：将弹窗自身的底部贴住触发器顶部, 因此弹窗会向上展开显示在上方.

anchored() 的定位方法:

方法说明
.anchor(Anchor)锚点(浮层的哪条边贴着参考点)
.position(Point<Pixels>)锚点坐标(默认取父元素原点)
.offset(point)在锚点基础上再偏移
.position_mode(AnchoredPositionMode::Window/Local)坐标相对窗口还是父元素
.attach(bounds, corner)直接指定参考 bounds, 不用父元素
.snap_to_window()浮层超出窗口时自动贴边收回
.snap_to_window_with_margin(px(8.))贴边收回并留出余量

悬浮提示的典型写法(取自 anchor 示例):

#![allow(unused)]
fn main() {
deferred(
    anchored()
        .anchor(corner) // 锚点: 按钮的对应角
        .position(position) // 锚点坐标: 按钮对应角的位置
        .position_mode(AnchoredPositionMode::Local) // 坐标相对父元素: 类似 position: absolute
        .snap_to_window() // 超出窗口自动贴边
        .child(
            div()
                .py_0p5() // 上下内边距: padding-top: 0.125rem; padding-bottom: 0.125rem
                .px_2()   // 左右内边距: padding-left: 0.5rem; padding-right: 0.5rem
                .bg(gpui::black().opacity(0.75)) // 半透明黑背景: background-color: rgb(0 0 0/0.75)
                .text_color(rgb(0xffffff)) // 文字颜色: color: #ffffff
                .rounded_sm() // 小圆角: border-radius: 0.125rem
                .shadow_sm()  // 小阴影: box-shadow: 0 1px 2px 0 rgb(0 0 0/0.05)
                .min_w(px(100.0)) // 最小宽度: min-width: 100px
                .text_sm() // 字号缩小: font-size: 0.875rem; line-height: 1.25rem
                .child(button.label.clone()),
        ),
)
}

16.3 on_mouse_down_out: 点击外部关闭

Popover 的标准交互是“点浮层外面就关掉“, 用 on_mouse_down_out 实现: 它在鼠标按下事件的捕获阶段检查位置, 按下点不在元素范围内就触发回调.

#![allow(unused)]
fn main() {
.when(self.open, |this| {
    this.child(
        deferred(
            anchored()
                .anchor(Anchor::TopLeft)
                .snap_to_window_with_margin(px(8.))
                .child(
                    popover()
                        .w_96() // 宽度: width: 24rem (384px)
                        .child("Click outside to close.")
                        // 关键: 鼠标在浮层外按下时关闭
                        .on_mouse_down_out(cx.listener(|this, _, _, cx| {
                            this.open = false; // 收起浮层
                            cx.notify(); // 通知 GPUI: 状态变了, 需要重新渲染
                        })),
                ),
        )
        .priority(1),
    )
})
}
  • 回调签名是 Fn(&MouseDownEvent, &mut Window, &mut App); 用 cx.listener(...) 包一层就能在回调里拿到视图状态(this).
  • 对应的 on_mouse_up_out(button, listener) 在鼠标抬起在元素外时触发.
  • 只想在浮层内部做点关闭按钮时, 配合 on_click 改同一个 open 状态即可.

16.4 多级嵌套 Popover(priority 层级控制)

级联菜单(菜单里再开菜单)就是嵌套 Popover: 每层一个 deferred, 用 priority 控制堆叠顺序, 数字大的画在上面(取自 popover 示例, 一级菜单 .priority(1), 二级菜单 .priority(2)):

#![allow(unused)]
fn main() {
// 二级菜单: 嵌套在一级浮层里, 优先级更高, 画在一级之上
deferred(
    anchored()
        .anchor(Anchor::TopLeft) // 锚点: 挂在触发按钮左上角
        .snap_to_window_with_margin(px(8.))
        .child(
            popover()
                .child("This is second level Popover with nested deferred!")
                .on_mouse_down_out(cx.listener(|this, _, _, cx| {
                    this.secondary_open = false;
                    cx.notify();
                })),
        ),
)
.priority(2), // 二级浮层层级: 比一级(1)高, 画在它上面
}

两个实战细节(示例里都踩过):

  1. 子浮层开着时要关掉父浮层的“点外面关闭“, 否则点子菜单会被当成“点外面“把父级一起关掉:
  2. 浮层要放在触发器内容之后渲染(.child(...) 接在按钮文字后面), 确保它在同层元素的上层. GPUI已支持多层嵌套 deferred, 级联几层都可以.
#![allow(unused)]
fn main() {
.when(!self.secondary_open, |this| {
    // 只有子浮层没开时才监听"点外面关闭"
    this.on_mouse_down_out(cx.listener(|this, _, _, cx| {
        this.open = false;
        cx.notify();
    }))
})
}

17. 动画系统

GPUI 的动画围绕 Animation(时长 + 缓动)和 AnimationExt::with_animation()(把动画绑到元素)展开, 一行链式声明就能跑起来. 另有弹簧动画(SpringAnimation)和手动逐帧(request_animation_frame)两条进阶路线.

17.1 Animation 结构体

Animation 描述“怎么动“: 播多久、是否循环、用什么缓动. 创建后通过 with_animation() 挂到元素上:

#![allow(unused)]
fn main() {
use gpui::*;
use std::time::Duration;

// 定义动画: 持续 2 秒, 无限循环
let animation = Animation::new(Duration::from_secs(2)) // 只收时长; 默认播放一次, linear 缓动
    .repeat()                      // 放完再来一轮(无限循环)
    .with_easing(bounce(ease_in_out)); // 缓动: bounce 包一层 ease_in_out, 来回弹
}

挂到元素上(取自 animation 示例的 SVG 旋转):

#![allow(unused)]
fn main() {
svg()
    .size_20() // 宽高都是 5 号尺寸的正方形: width: 5rem; height: 5rem (80px)
    .path(ARROW_CIRCLE_SVG) // SVG 资源(见 17.4 的 AssetSource)
    .text_color(gpui::black()) // 图标着色: color: #000000
    .with_animation(
        "image_circle", // 动画 id: 同一元素多个动画靠 id 区分
        Animation::new(Duration::from_secs(2))
            .repeat()                      // 无限循环
            .with_easing(bounce(ease_in_out)), // 缓动函数
        |svg, delta| {
            // delta: 归一化进度 0.0 -> 1.0, 每帧回调一次
            svg.with_transformation(Transformation::rotate(percentage(delta)))
        },
    ),
}

Animation 的配置方法:

方法说明
Animation::new(duration)创建动画, 只收时长
.repeat()无限循环(默认只播一次)
.repeat_synced()循环且与整个 App 共享时钟(多个动画相位同步)
.with_easing(fn)缓动函数: Fn(f32) -> f32, 输入输出都是归一化进度
.with_max_fps(f32)限制每秒重绘次数, 省电

with_animation(id, animation, animator) 的 animator 收 (元素, delta), 返回改好的元素; 动画元素挂载后自动逐帧调用它, 播完一次(one-shot)停在结束状态, repeat() 则一直转下去. 不想要某个动画时, 用 .when(self.active, ...) 把整个元素(或动画)从树里拿掉.

NOTE: Animation::new 只收 Duration, 没有 Animation::new(cx.entity(), active) 这种“实体 + 开关“签名, 也没有 .with_duration()/.ease_out()/.linear()/.repeat(AnimationRepeat::Forever) 这些方法 —— 时长在 Animation::new() 里给, 循环是 .repeat(), 缓动统一走 .with_easing(闭包).

NOTE: with_animation 的第一个参数是动画 id(impl Into<ElementId>), 三参数缺一不可; with_animation(animation, |div, progress| ...) 这种两参写法 没有. 还要 use gpui::AnimationExt as _; 把 trait 引进来(它不在 prelude 里).

17.2 Easing 函数

缓动函数就是普通的 fn(f32) -> f32: 输入线性时间(0..1), 输出动画进度(可以超出 0..1, 比如弹簧过冲).GPUI内置这些:

函数效果
linear匀速, 就是 delta 本身
quadratic平方加速: delta * delta
ease_in_out缓入缓出, 最常用
ease_out_quint()五次方缓出(注意带括号, 返回的是闭包)
bounce(easing)把任意缓动正放一遍再倒放一遍(来回弹)
pulsating_between(min, max)呼吸/脉动, 输出在 min..max 之间

NOTE: 缓动就是函数, 没有 Easing 枚举或结构体, 也没有 ease_in()/ease_out()/spring() 这三个函数 —— 只有 ease_in_out 和 ease_out_quint(); “spring()” 不是缓动, 弹簧是下面这套独立 API.

弹簧动画: 要“惯性过冲、中途改目标能接上速度“的物理手感, 用 SpringAnimation(完整演示在 cargo run --example animation):

#![allow(unused)]
fn main() {
div()
    .absolute()          // 绝对定位: position: absolute
    .top_1()             // 顶部偏移: top: 0.25rem (4px)
    .size(px(24.0))      // 宽高 24px: width: 24px; height: 24px
    .rounded_full()      // 圆形: border-radius: 9999px
    .with_spring(
        "spring-position", // 动画 id: id 会记住弹簧的位置和速度, 改目标值平滑接力
        SpringAnimation::new(SpringConfig::new(170.0, spring_damping, 1.0)) // 刚度、阻尼、质量
            .to(spring_position) // 目标位置
            .with_epsilon(0.25), // 收敛阈值: 距目标小于它就停
        |this, left| this.left(left), // 每帧把弹簧输出的位置写进样式
    ),
}

17.3 变换 Transformation

Transformation 是 SVG 的绘制变换, 通过 .with_transformation() 应用: 只影响绘制, 不改布局也不影响命中测试(鼠标判定还是按原位置).

构造说明
Transformation::scale(size(1.2, 1.2))缩放: 两个轴的倍率
Transformation::translate(point(px(10.), px(0.)))平移: (x, y) 像素偏移
Transformation::rotate(percentage(delta))旋转: 角度是 Radians
.with_scaling()/.with_translation()/.with_rotation()在一个变换上继续组合其他分量

percentage(x) 把 0..1 映射成整圈的比例(0.25 是 90°, 1.0 是 360°), 因此动画里 Transformation::rotate(percentage(delta)) 正好转一整圈. 旋转、缩放、平移可以经 with_* 组合在一个变换里.

对 div 而言没有 Transformation, 动画闭包里改的是样式:

#![allow(unused)]
fn main() {
// 动画驱动的是样式值: 每帧把进度换算成 left
|div, delta| div.left(px(delta * 200.0)), // 位移 200px: left: 0px -> 200px
}

NOTE: Transformation 一族是 Svg 的方法(.with_transformation()), 没有通用元素上的 .scale()/.rotate()/.translate() 链式变换; div 动画请在闭包里改样式(.left()/.w()/.bg() 等, 弹簧示例就是这么做的).

17.4 AssetSource 加载动画资源

动画里的 SVG(转圈图标、加载指示器)通过 AssetSource 加载, 约定见第 6 章. animation 示例从文件系统读资源:

#![allow(unused)]
fn main() {
struct Assets {}

impl AssetSource for Assets {
    // 加载资源: 返回文件字节(图片/SVG 都是二进制, 不是字符串)
    fn load(&self, path: &str) -> Result<Option<std::borrow::Cow<'static, [u8]>>> {
        std::fs::read(path)
            .map(Into::into)
            .map_err(Into::into)
            .map(Some)
    }

    // 列出某目录下的资源名
    fn list(&self, path: &str) -> Result<Vec<SharedString>> {
        Ok(std::fs::read_dir(path)?
            .filter_map(|entry| {
                Some(SharedString::from(entry.ok()?.path().to_string_lossy().into_owned()))
            })
            .collect())
    }
}

// 应用启动时注册: 之后 svg().path("...") 就会走 Assets::load
application().with_assets(Assets {}).run(|cx: &mut App| { /* ... */ });
}

NOTE: AssetSource 只有 load(&self, path)/list(&self, path) 两个方法(见 6.4), 没有 load_asset(&mut self, path, cx) -> Task<...> 这种异步签名. 资源加载是同步取字节, 异步解码由GPUI内部处理.

17.5 手动动画: window.request_animation_frame()

复杂的逐帧逻辑(粒子、游戏循环)可以自己驱动. 两个 API 配合:

方法说明
window.request_animation_frame()请求下一帧重绘(无参数, 没有回调)
window.on_next_frame(闭包)/cx.on_next_frame(window, 闭包)当前帧渲染完后执行闭包, 在里面预约下一帧

手动循环的骨架: 在回调里推进状态、cx.notify() 触发重绘, 再预约下一帧:

#![allow(unused)]
fn main() {
impl Spinner {
    /// 每帧把角度推进一点, 然后预约下一帧, 形成动画循环
    fn tick(&mut self, window: &mut Window, cx: &mut Context<Self>) {
        if !self.running {
            return; // 开关关掉就不再续约, 动画自然结束
        }
        self.angle = (self.angle + 6.0) % 360.0; // 每帧转 6 度
        cx.notify(); // 通知 GPUI: 状态变了, 需要重新渲染
        cx.on_next_frame(window, |this, window, cx| {
            this.tick(window, cx); // 下一帧继续
        });
    }
}
}

渲染时直接用 self.angle 换算样式即可; request_animation_frame() 只在“需要一帧重绘但没有自己的回调“时用(它内部就是通知当前视图刷新).

NOTE: window.request_animation_frame() 没有 (cx.entity(), 闭包) 这种带回调的签名 —— 回调请用 cx.on_next_frame(window, ...) 或 window.on_next_frame(...). 另外装饰性动画(spinner、脉动)优先用 with_animation, 它会自动尊重系统的“减少动态效果“设置(App::reduce_motion); 手动循环时要自己检查这个状态, 跳过帧请求.

💡 提示: 动画时长的常见选择: 界面过渡 150-300ms, 加载指示 800-1200ms 循环. 同时运行的动画越多帧率压力越大, 长列表里避免给每行都挂动画(配合第 15 章的虚拟化只让可见行动起来).

18. 底层绘图

布局系统(div、图片、文本)覆盖不了的图形 —— 曲线、饼图、自由涂鸦 —— 用 canvas() 进行底层绘图: 在元素的绘制阶段直接向场景提交图形, 由 PathBuilder 构建矢量路径, 再用 window.paint_path/window.paint_quad 画上去.

18.1 canvas() 函数

canvas() 创建一个“自己动手画“的元素, 它收两个闭包: prepaint 和 paint:

#![allow(unused)]
fn main() {
use gpui::*;

// 签名: canvas(prepaint, paint)
//   prepaint: FnOnce(Bounds<Pixels>, &mut Window, &mut App) -> T
//   paint:   FnOnce(Bounds<Pixels>, T, &mut Window, &mut App)
canvas(
    // prepaint: 布局完成后先执行, 可以做测量、预构建路径, 返回值 T 传给 paint
    move |bounds, window, cx| {
        // ...
    },
    // paint: 真正绘制, 第二个参数就是 prepaint 的返回值 T
    move |bounds, t, window, cx| {
        // ...
    },
)
}
  • bounds 是元素在布局中的实际矩形(窗口坐标系), 所有绘图坐标都是绝对坐标.
  • 两个闭包都是 FnOnce, 每帧渲染时随元素一起传入.
  • 不需要 prepaint 做事就返回 (), 示例里常写 move |_, _, _| {}.
  • canvas() 是自由函数(不是 div() 的方法), 一般包在 .child(...) 里; 返回的 Canvas 实现了 Styled, 可以继续链式设置尺寸: .size_full()、.w(px(200.0)) 等.

一个最小的圆(取自 examples/painting.rs 的画法):

#![allow(unused)]
fn main() {
canvas(
    move |_, _, _| {}, // prepaint 无事可做
    move |bounds, _, window, _| {
        let center = bounds.center();
        let radius = bounds.size.width * 0.25; // Pixels 只能乘 f32, 没有除 f32

        // 用两段椭圆弧拼一个整圆
        let mut builder = PathBuilder::fill();
        builder.move_to(point(center.x + radius, center.y));
        builder.arc_to(point(radius, radius), px(0.), false, false, point(center.x - radius, center.y));
        builder.arc_to(point(radius, radius), px(0.), false, false, point(center.x + radius, center.y));
        builder.close();
        let path = builder.build().unwrap();
        window.paint_path(path, rgb(0x3b82f6)); // 填充蓝色圆
    },
)
.size(px(120.0)) // 画布自身 120x120: width: 120px; height: 120px
}

NOTE:GPUI没有 PaintCtx 这个类型. “paint 回调获取 PaintCtx” 的说法不成立 —— 绘制阶段拿到的是 &mut Window, 绘图方法是 window.paint_path()/window.paint_quad().

💡 提示: canvas 的闭包每帧执行, 内容完全由闭包捕获的状态决定. 状态变了(比如鼠标画了新线)要 cx.notify() 通知GPUI重绘, 否则画面停在旧内容上; 窗口尺寸变化导致 bounds 改变时同理.

18.2 PathBuilder 路径构建

PathBuilder 提供类似 SVG path 的 API 构建矢量路径, 构建完 build() 得到 Path<Pixels> 交给 paint_path.

基本操作:

方法说明
move_to(point)移动画笔到起点(不绘制)
line_to(point)从当前点画直线到目标点
close()闭合当前子路径(连回起点)
add_polygon(&points, closed)一次性加多边形
translate(p)/scale(f)/rotate(deg)对整条路径做几何变换
dash_array(&[px(4.), px(2.)])虚线样式(描边路径用)
build()完成构建, 返回 Result<Path<Pixels>>

填充与描边模式: 在创建 builder 时就决定, 不是绘制时传 Fill/Stroke:

写法模式
PathBuilder::fill()填充模式, 填充封闭区域
PathBuilder::stroke(width)描边模式, width 是线宽(如 px(2.0))

NOTE:GPUI没有 PathBuilder::new(), 也没有 Fill::new()/Stroke::new() 这类“绘制模式“对象 —— 填充还是描边由 PathBuilder::fill()/PathBuilder::stroke() 决定, build() 的结果直接交给 window.paint_path.

#![allow(unused)]
fn main() {
// 1. 填充三角形
let mut builder = PathBuilder::fill(); // 填充模式
builder.move_to(point(px(60.), px(20.)));
builder.line_to(point(px(20.), px(80.)));
builder.line_to(point(px(100.), px(80.)));
builder.close(); // 闭合路径
let path = builder.build().unwrap();
window.paint_path(path, rgb(0xef4444)); // 红色填充

// 2. 描边菱形
let mut builder = PathBuilder::stroke(px(3.0)); // 描边模式, 线宽 3px
builder.move_to(point(px(160.), px(20.)));
builder.line_to(point(px(200.), px(50.)));
builder.line_to(point(px(160.), px(80.)));
builder.line_to(point(px(120.), px(50.)));
builder.close();
let path = builder.build().unwrap();
window.paint_path(path, rgb(0x22c55e)); // 绿色描边
}

18.3 arc_to/curve_to 曲线路径

除直线外, PathBuilder 支持圆弧和贝塞尔曲线.

arc_to —— 椭圆弧(签名与 SVG path 的 A 命令一致):

参数说明
radii: Point<Pixels>椭圆两个半径, point(px(30.), px(30.)) 即正圆
x_rotation: Pixels椭圆轴旋转角度(度), 一般传 px(0.)
large_arc: bool走大弧还是小弧
sweep: bool顺时针(true)还是逆时针(false)
to: Point<Pixels>弧的终点
 
#![allow(unused)]
fn main() {
// 从当前点画半圆弧到直径另一端(配合第二次 arc_to 就是整圆, 见 18.1)
builder.move_to(point(center.x + radius, center.y));
builder.arc_to(point(radius, radius), px(0.), false, false, point(center.x - radius, center.y));
}

NOTE: arc_to 没有 “圆心 + 半径 + 起始角 + 扫过角” 这种签名. 原文的 arc_to(center, radius, start_angle, sweep_angle) 是别的图形库的写法, 在GPUI里编译不过 —— 圆心、角度都要自己换算成“起点 + 终点 + 两个半径“传进去.

curve_to —— 贝塞尔曲线: curve_to(to, ctrl) 是二次贝塞尔(一个控制点), 注意终点在前、控制点在后; 三次贝塞尔(两个控制点)用 cubic_bezier_to(to, control_a, control_b).

NOTE: 原文的 curve_to(control1, control2, end_point) 三次贝塞尔写法不对 —— curve_to 是二次贝塞尔, 且参数顺序相反.

#![allow(unused)]
fn main() {
// 一条下垂的曲线: 从左下到右下, 控制点把线往下拉
let mut builder = PathBuilder::stroke(px(2.0));
builder.move_to(point(px(40.), px(40.)));
builder.curve_to(
    point(px(200.), px(40.)), // to: 终点
    point(px(120.), px(100.)), // ctrl: 控制点(往下拉)
);
let path = builder.build().unwrap();
window.paint_path(path, gpui::blue());
}

18.4 paint_path/paint_quad

构建好的路径和矩形通过 Window 的绘制方法提交:

API用途说明
window.paint_path(path, color)填充/描边任意路径填充还是描边早已由 PathBuilder 决定; color 收 impl Into<Background>

18.5 鼠标绘图交互(核心思路)

examples/painting.rs 是一个完整画板: 按住左键拖动涂鸦, 按住 Shift 画水平/垂直直线. 核心是“事件改状态 + cx.notify() 触发 canvas 重绘“:

  1. on_mouse_down 记录起点, 开始一条新笔画;
  2. on_mouse_move 把当前点追加进笔画, cx.notify() 重绘;
  3. on_mouse_up 结束当前笔画;
  4. Shift 吸附: 把当前点钉到过起点的水平或垂直线上.
#![allow(unused)]
fn main() {
.on_mouse_down(
    gpui::MouseButton::Left,
    cx.listener(|this, ev: &MouseDownEvent, _, _| {
        this._painting = true;
        this.start = ev.position;
        this.lines.push(vec![ev.position]); // 新笔画
    }),
)
.on_mouse_move(cx.listener(|this, ev: &MouseMoveEvent, _, cx| {
    if !this._painting { return; }
    let mut pos = ev.position;
    if ev.modifiers.shift {
        // Shift 吸附到水平/垂直方向
        let dx = pos.x - this.start.x;
        let dy = pos.y - this.start.y;
        if dx.abs() > dy.abs() {
            pos.y = this.start.y;
        } else {
            pos.x = this.start.x;
        }
    }
    if let Some(path) = this.lines.last_mut() {
        path.push(pos);
    }
    cx.notify(); // 通知重绘: canvas 闭包按新数据再画一遍
}))
}

每帧绘制时把所有笔画转成 PathBuilder::stroke 路径, 逐段 line_to, 一次 paint_path 画完; 要虚线就在 builder 上 .dash_array(&[px(4.), px(2.)]).

19. 渐变与图案

渐变和图案本质都是 Background 值, 既能做元素背景(见 4.4、4.5), 也能填充 canvas 自绘的任意路径. 本章重点讲绘图场景里的用法和色彩空间, 与第 4 章互补不重复.

19.1 linear_gradient 线性渐变

linear_gradient() 构造线性渐变, 与纯色一样直接塞进 .bg() 或 paint_path/paint_quad:

#![allow(unused)]
fn main() {
use gpui::{linear_color_stop, linear_gradient};

// linear_gradient(角度, 起始色标, 结束色标)
let gradient = linear_gradient(
    45.0, // 角度(度): 0 = 向上, 顺时针增大
    linear_color_stop(gpui::red(), 0.0), // 起始色标: 颜色 + 位置(0.0~1.0)
    linear_color_stop(gpui::blue(), 1.0), // 结束色标
);

div().bg(gradient) // 渐变当背景: background-image: linear-gradient(45deg, ...)
}

角度取 0~360 的度数: 0 是“从下往上“, 90 是“从左往右“, 180 是“从上往下“, 与 CSS linear-gradient 的方向约定一致. 渐变只收两个色标(from/to), 中间不能插更多.

在 canvas 里填充路径(取自 examples/gradient.rs, 梯形内红蓝渐变):

#![allow(unused)]
fn main() {
canvas(move |_, _, _| {}, move |bounds, _, window, _| {
    // square_bounds/horizontal_offset/vertical_offset 由 bounds 算出(见完整示例)
    let mut builder = PathBuilder::fill();
    builder.move_to(square_bounds.bottom_left());
    builder.line_to(square_bounds.origin + point(horizontal_offset, vertical_offset));
    builder.line_to(square_bounds.top_right() + point(-horizontal_offset, vertical_offset));
    builder.line_to(square_bounds.bottom_right());
    builder.close();
    let path = builder.build().unwrap();

    // 渐变直接当"颜色"用, 填充任意路径
    window.paint_path(
        path,
        linear_gradient(
            180., // 从上往下
            linear_color_stop(gpui::red(), 0.),
            linear_color_stop(gpui::blue(), 1.),
        ),
    );
})
}

NOTE: linear_gradient 没有 “起止点 + 色标列表” 的签名. 原文的 linear_gradient(start_point, end_point, color_stops, color_space) 编译不过 —— 真实签名是 linear_gradient(angle, from, to): 收一个角度 + 恰好两个色标, 没有多色标, 也没有径向/锥形渐变.

NOTE: 色标函数是 linear_color_stop(color, percentage) —— 颜色在前, 位置在后; 原文的 linear_color_stop(offset, color) 顺序写反了.

渐变填充任意形状都没问题, 比如 painting.rs 里给星形填黄橙渐变:

#![allow(unused)]
fn main() {
// 十角星路径(略): 逐点 line_to 后 close
let path = builder.build().unwrap();
window.paint_path(
    path,
    linear_gradient(
        180., // 从上往下
        linear_color_stop(rgb(0xFACC15), 0.7), // 黄色铺到 0.7 处, 之后过渡到橙
        linear_color_stop(rgb(0xD56D0C), 1.), // 橙色收尾
    )
    .color_space(ColorSpace::Oklab), // 感知均匀插值, 黄橙过渡更顺
);
}

💡 提示: 渐变条带的位置不必铺满 0~1. 两个色标写 0.05 和 0.95, 渐变带压缩到中间, 两端各留一段纯色; 两个色标位置相同(比如都是 0.5)得到的是硬边分界. 渐变还支持 .opacity(0.5) 整体调透明度.

19.2 ColorSpace 色彩空间

色彩空间决定两个色标之间怎么插值.GPUI支持两种, 用 .color_space() 链式设置:

取值特点适用场景
ColorSpace::Srgb在屏幕 RGB 空间线性插值, 与 CSS 默认行为一致; 中段容易发灰发暗要和网页/设计稿像素级对齐时
ColorSpace::Oklab在感知均匀的空间插值, 过渡自然, 中间色接近人眼预期UI 渐变、品牌色过渡(想要好看就选它)
 
#![allow(unused)]
fn main() {
let gradient = linear_gradient(
    90.0,
    linear_color_stop(gpui::red(), 0.0),
    linear_color_stop(gpui::blue(), 1.0),
)
.color_space(ColorSpace::Oklab); // 在 Oklab 空间插值: 红蓝之间会出紫色, 而不是脏灰色
}

为什么需要它: 从红到蓝的渐变在 sRGB 里线性插值, 中段是偏暗的“脏紫色“; Oklab 在感知均匀的空间里插值, 中段呈现自然的紫色过渡. examples/gradient.rs 顶部有个切换按钮, 点一下就能对比两种空间下的所有渐变. 想自己做对比实验, 同一组色标画两根条即可:

#![allow(unused)]
fn main() {
// 同一对色标, 只换插值空间
let stops = |space: ColorSpace| {
    linear_gradient(
        90.0,
        linear_color_stop(gpui::red(), 0.0),
        linear_color_stop(gpui::blue(), 1.0),
    )
    .color_space(space)
};

div().flex().gap_3() // 弹性布局: display: flex; gap: 0.75rem (12px)
    .child(div().flex_1().h_10().bg(stops(ColorSpace::Srgb)))  // 左: Srgb, 中段发灰
    .child(div().flex_1().h_10().bg(stops(ColorSpace::Oklab))) // 右: Oklab, 中段是自然的紫
}

NOTE: 默认值是 ColorSpace::Srgb, 不是 Oklab —— 想要感知均匀的过渡必须显式 .color_space(ColorSpace::Oklab). “GPUI 推荐默认使用 Oklab“的说法不准确, 推荐与否是审美选择, 默认行为跟 CSS 一致.

💡 提示: 色彩空间只影响 LinearGradient 的插值. 纯色、图案(pattern_slash/checkerboard)没有插值过程, 设置 color_space 对它们无效.

19.3 pattern_slash 图案填充

图案也是 Background 的一种,GPUI内置两种:

函数效果参数
pattern_slash(color, width, interval)斜线网纹线宽、间距(普通 f32, 不套 px())
checkerboard(color, size)棋盘格格子边长
 
#![allow(unused)]
fn main() {
// 斜线图案: 红色斜线, 线宽 4, 间距 4
div().w(px(256.0)).h(px(56.0)).bg(pattern_slash(gpui::red(), 4.0, 4.0))

// 棋盘格: 红色与透明相间的方格, 格子边长 8
div().size(px(64.0)).bg(checkerboard(gpui::red(), 8.0))
}

在 canvas 里同样能用 —— 图案就是 paint_quad 的背景参数:

#![allow(unused)]
fn main() {
canvas(move |_, _, _| {}, move |bounds, _, window, _| {
    window.paint_quad(quad(
        bounds,
        px(12.0),                       // 圆角: border-radius: 12px
        pattern_slash(gpui::red(), 4.5, 4.5), // 斜线图案当背景
        px(0.),
        gpui::transparent_black(),
        Default::default(),
    ));
})
}

NOTE: 图案只有 pattern_slash 和 checkerboard 两种, 没有 pattern_grid/pattern_dots/pattern_checker 这些函数. 想要网格或点阵, 在 canvas 里用 paint_path 自己画.

参数怎么取: width 和 interval 是普通 f32(不套 px()), 分别是斜线的线宽和相邻斜线的间距. 要让不同尺寸的元素斜线密度一致, 按元素高度等比取值, pattern.rs 里就是这么做的:

#![allow(unused)]
fn main() {
// 高 56px 的条: 线宽 = 间距 = 56/6, 斜线粗细跟着元素走
div().w(px(256.0)).h(px(56.0)).bg(pattern_slash(gpui::red(), 56.0/6.0, 56.0/6.0))

// 同样线宽间距, 换个颜色就是另一种底纹
div().w(px(256.0)).h(px(56.0)).bg(pattern_slash(gpui::blue(), 56.0/6.0, 56.0/6.0))
}

💡 提示: 斜线图案常用来表达“禁用/加载中/装饰底纹“. 要“绿底 + 斜线“的叠加效果, 把纯色背景和图案放在父子两层元素上(外层 .bg(gpui::green().opacity(0.16)), 内层 .bg(pattern_slash(...))), 图案本身只有一种颜色, 不带底色.

19.4 渐变与图案功能对比

四类 Background 各有所长, 且同一个值可以同时用于 .bg()、paint_path、paint_quad —— 一份填充三处用:

填充构造参数典型用途
纯色rgb()/gpui::red()颜色常规背景、路径填充
线性渐变linear_gradient()角度 + 两个色标 + 可选色彩空间按钮、卡片装饰、渐变形状
斜线图案pattern_slash()颜色、线宽、间距禁用态、加载态、底纹
棋盘格checkerboard()颜色、格子边长透明底衬、对齐检查

渐变 vs 图案: 渐变是连续的颜色过渡(受色彩空间影响), 图案是平铺的重复纹理(与色彩空间无关). 渐变适合做“一块色面“, 图案适合做“提示性的纹理“.

元素背景 vs canvas 填充: .bg() 走样式系统, 跟随布局尺寸自动铺满; canvas 里的 paint_path/paint_quad 是自由绘图, 坐标、形状、叠放次序全由自己控制(见第 18 章). 渐变的角度语义两边完全一致(0 向上, 顺时针), 但铺满的是各自绘制内容所在的区域, 也不能像 CSS 那样单独指定渐变线的起止点 —— 能调的只有角度和两个色标的位置.

#![allow(unused)]

pub fn prompt<T: Clone + Into<PromptButton>>(
    &mut self,
    level: PromptLevel,       // Info/Warning/Critical
    message: &str,            // 主提示文字
    detail: Option<&str>,     // 补充说明, 可 None
    answers: &[T],            // 按钮列表
    cx: &mut App,
) -> oneshot::Receiver<usize>  // 异步返回被点按钮的下标
}

按钮既可以直接传 &str(仅 “ok”/“cancel” 会映射成 Ok/Cancel 按钮, 其他文字都算 Other), 也可以用 PromptButton 显式指定语义 —— 中文标签建议用后者, 保留“确定/取消“的按钮类型:

#![allow(unused)]
fn main() {
// 简单版: &str 里的 "ok"/"cancel" 自动映射成 OK/Cancel 按钮
let answer = window.prompt(PromptLevel::Info, "Are you sure?", None, &["OK", "Cancel"], cx);

// 中文按钮: 显式构造 PromptButton
let answer = window.prompt(
    PromptLevel::Info,
    "Are you sure?",
    None,
    &[PromptButton::ok("确定"), PromptButton::cancel("取消")],
    cx,
);

// 结果是异步的: 在任务里 await 出按钮下标
cx.spawn(async move |_| {
    if answer.await.unwrap() == 0 {
        println!("You have clicked Ok");
    }
})
.detach();
}

21. 多屏定位

现代桌面应用常常要面对多显示器: 窗口开在哪块屏、摆在什么位置、两块屏 DPI 不一致怎么办. GPUI通过 cx.displays() 枚举所有显示器, 配合 Bounds 的方位方法, 可以在任意屏幕上精确定位窗口.

21.1 多显示器支持

App::displays() 返回系统当前所有显示器, 每个是 Rc<dyn PlatformDisplay>, 从中可以拿到唯一标识 DisplayId 和屏幕矩形:

#![allow(unused)]
fn main() {
use gpui::*;

/// 枚举所有显示器并打印位置和尺寸
fn list_displays(cx: &App) {
    for (i, display) in cx.displays().iter().enumerate() {
        let bounds = display.bounds(); // 显示器的矩形(全局坐标系)
        println!(
            "显示器 {}: {:?} 位置=({}, {}) 尺寸={}x{}",
            i,
            display.id(),
            bounds.origin.x,
            bounds.origin.y,
            bounds.size.width,
            bounds.size.height,
        );
    }
}
}

PlatformDisplay 提供的方法:

方法说明
id()返回 DisplayId, 开窗时用来指定目标显示器
uuid()跨重启稳定的 UUID(Result<Uuid>), 适合持久化“上次所在的屏“
bounds()显示器矩形 Bounds<Pixels>(整个屏幕, 含菜单栏/任务栏)
visible_bounds()可见区域, 排除 dock/任务栏, 摆窗口用它更合适
default_bounds()平台建议的默认窗口位置
refresh_interval()刷新间隔(可变刷新率屏报最大值)

DisplayId 是不透明标识符, 通过 display.id() 获取, 放进 WindowOptions::display_id 就能把窗口开在指定屏幕上. 另有两个查找入口: cx.primary_display() 返回主显示器, cx.find_display(id) 按 id 查找; window.display(cx) 则能查出某个窗口当前在哪块屏上.

NOTE: 显示器缩放因子挂在窗口上(window.scale_factor()), 要找主屏就用 cx.primary_display(), 再比较返回的 id().

21.2 Bounds 结构

屏幕和窗口的矩形都用 Bounds<T> 描述: 左上角 origin: Point<T> 加上尺寸 size: Size<T>. 屏幕坐标是 Bounds<Pixels>:

#![allow(unused)]
fn main() {
/// 简化版定义(实际是泛型结构体)
struct Bounds<T> {
    origin: Point<T>, // 左上角坐标
    size: Size<T>,   // 宽高
}

struct Point<T> {
    x: T, // X 坐标
    y: T, // Y 坐标
}

struct Size<T> {
    width: T, // 宽度
    height: T, // 高度
}
}

构造矩形最常用的是自由函数 point(x, y) 和 size(w, h), 此外还有 Bounds::new(origin, size)、Bounds::from_corners(top_left, bottom_right)、Bounds::centered_at(center, size)、Bounds::from_anchor_and_size(anchor, origin, size)(指定角点 + 尺寸). Point 之间可以加减, 定位时直接对角点做偏移:

#![allow(unused)]
fn main() {
// 从屏幕左上角向右下偏移 150px, 得到窗口左上角
let origin = screen.bounds().origin + point(px(150.0), px(150.0));
}

NOTE: display.bounds() 返回的是 Bounds<Pixels>(逻辑像素), 不是 Bounds<DevicePixels>. 需要物理像素时用 bounds.to_device_pixels(scale_factor) 换算, scale_factor 来自 window.scale_factor().

21.3 屏幕方位方法

Bounds 提供一组方位方法, 直接返回矩形上的关键点(都是 Point<T>), 窗口定位、弹层对齐时不用手算:

方法返回值说明
bounds.originPoint左上角坐标
bounds.top_right()Point右上角坐标
bounds.bottom_left()Point左下角坐标
bounds.bottom_right()Point右下角坐标
bounds.top_center()Point上边中点
bounds.bottom_center()Point下边中点
bounds.left_center()Point左边中点
bounds.right_center()Point右边中点
bounds.center()Point中心点
bounds.corner(Anchor::BottomLeft)Point按 8 个 Anchor 取角点/边中点

另有 4 个只返回边线坐标的方法 top()/bottom()/left()/right()(返回 T 而不是点), 以及 contains(&point) 判断点是否落在矩形内、intersects(&other) 判断两矩形是否相交.

NOTE: Bounds 没有 top_left() 方法, 左上角就是字段 bounds.origin; 想和其他角写法保持一致可以用 bounds.corner(Anchor::TopLeft).

fn main() {

// 判断窗口中心是否落在这块屏上

21.4 多屏定位示例

在指定屏幕上开窗. 把算好的屏幕坐标和 DisplayId 一起塞进 WindowOptions. window_positioning.rs 遍历所有屏幕, 在每块屏的右上角开一窗:

#![allow(unused)]
fn main() {
use gpui::*;

fn open_on_each_display(cx: &mut App) {
    for screen in cx.displays() {
        let size = Size { width: px(350.0), height: px(75.0) };
        let margin = px(150.0);

        // 窗口摆在屏幕右上角: 横向退一个窗口宽加边距, 纵向进一个边距
        let bounds = Bounds {
            origin: screen.bounds().top_right() - point(size.width + margin, -margin),
            size,
        };

        cx.open_window(
            WindowOptions {
                window_bounds: Some(WindowBounds::Windowed(bounds)), // 窗口位置和大小
                display_id: Some(screen.id()), // 开在哪块屏上
                ..Default::default()
            },
            |_, cx| cx.new(|_| MyApp),
        )
        .unwrap();
    }
}
}

window_bounds 收 WindowBounds 枚举, 三种取值里的 Bounds 都是“还原尺寸“:

取值说明
WindowBounds::Windowed(bounds)普通窗口, 按给定 bounds 摆放
WindowBounds::Maximized(bounds)打开即最大化(bounds 是还原后的尺寸)
WindowBounds::Fullscreen(bounds)打开即全屏(bounds 是还原后的尺寸)

WindowBounds::get_bounds() 取出内部的 Bounds<Pixels>; WindowBounds::centered(size, cx) 一步得到“主屏居中“的取值.

窗口居中. 通用算法是“容器原点 + (容器尺寸 - 自身尺寸)/2“:

#![allow(unused)]
fn main() {
/// 计算 content 在 container 内居中时的左上角
fn center_origin(content: Size<Pixels>, container: Bounds<Pixels>) -> Point<Pixels> {
    point(
        container.origin.x + (container.size.width - content.width)/2.0,
        container.origin.y + (container.size.height - content.height)/2.0,
    )
}
}

不过GPUI已经内置了居中构造, 通常不必手写:

#![allow(unused)]
fn main() {
// 在主屏可见区域内居中(第一个参数可指定 DisplayId, None 表示主屏)
let bounds = Bounds::centered(None, size(px(600.0), px(600.0)), cx);
// 同类的还有: 生成最大化尺寸的 Bounds::maximized(display_id, cx)
}

window_shadow.rs 就是用 Bounds::centered(None, size(px(600.0), px(600.0)), cx) 开出居中窗口的.

跨屏移动窗口. NOTE: GPUI没有 move_window()/window.move_to() 这类运行时挪窗口的 API, 窗口位置只在创建时由 window_bounds 决定, 之后用户拖动由系统处理. 想把窗口“挪“到另一块屏, 只能用目标屏的 bounds 重新开一扇窗再关掉旧的.

💡 提示: window_positioning.rs 遍历 cx.displays(), 在每块屏的四角、四边中点和中心各开一窗(共 9 个), 是检验方位方法坐标系最直观的例子.

多屏 DPI: 不同屏幕的缩放因子可能不同(如 1x 外接屏 + 2x Retina 内置屏). display.bounds() 用逻辑像素 Pixels; 窗口拖到另一块屏时GPUI自动按 window.scale_factor() 重算缩放, 无需手动处理. 要做精确物理像素对齐(如贴边吸附)时, 用 bounds.to_device_pixels(scale_factor) 换算后再比较. 需要在窗口换屏时做点什么(比如记住“这块屏上的最大化尺寸“), 订阅 cx.observe_window_display(window, ...)(窗口移动到另一块屏或所在屏刷新率变化时触发).

22. 自定义窗口装饰

原生标题栏千篇一律, 很多应用(VS Code、Spotify 风格)选择自己画标题栏和边框.GPUI用 WindowDecorations 决定装饰由谁绘制, 配合拖拽、缩放、阴影等 API, 可以做出完全定制的窗口外观.

22.1 WindowDecorations 枚举

WindowDecorations 是开窗选项, 放在 WindowOptions::window_decorations 里, 只有两个取值:

枚举值行为适用场景
WindowDecorations::Server系统(窗口管理器)绘制原生标题栏和边框标准应用窗口(默认)
WindowDecorations::Client应用自己渲染标题栏和边框自定义 UI 风格
 
#![allow(unused)]
fn main() {
use gpui::*;

let options = WindowOptions {
    window_decorations: Some(WindowDecorations::Client), // 装饰由应用自己画
    ..Default::default()
};
}

💡 提示: 平台不一定满足装饰请求(源码原话: “The platform may ignore requests it cannot satisfy”), 这个选项主要在 Linux(X11/Wayland)生效. macOS/Windows 隐藏系统标题栏走的是 TitlebarOptions::appears_transparent: true, 四种标题栏组合的对照见 cargo run --example window_movable.

运行时查询用的是另一个枚举. window.window_decorations() 返回 Decorations, 告诉你当前实际生效的装饰形态:

#![allow(unused)]
fn main() {
match window.window_decorations() {
    Decorations::Server => {
        // 系统装饰, 标题栏和边框都不用自己画
    }
    Decorations::Client { tiling } => {
        // tiling: Tiling { top, left, right, bottom, .. }
        // 被平铺贴靠的边不用画圆角和阴影
    }
}
}

Tiling 有 top/left/right/bottom 四个布尔字段和 is_tiled() 方法, 表示窗口哪些边正被系统平铺(贴靠屏幕边缘或被平铺器接管)——这些边上圆角和阴影应该关掉.

NOTE: 查询装饰状态用 window.window_decorations(), 返回的是 Decorations(带 tiling 信息), 不是 WindowDecorations; 后者只出现在 WindowOptions 里.

22.2 自定义标题栏实现

自定义标题栏就是一个普通 div(): 摆上标题文字和按钮, 在鼠标按下时调 window.start_window_move() 把拖拽交给系统:

#![allow(unused)]
fn main() {
div()
    .flex()                  // 弹性布局: display: flex
    .items_center()          // 垂直居中: align-items: center
    .h(px(36.0))             // 标题栏高度: height: 36px
    .bg(rgb(0x1a1b2e))       // 背景色: background-color: #1a1b2e
    .px_3()                  // 左右内边距: padding-left: 0.75rem; padding-right: 0.75rem
    .on_mouse_down(MouseButton::Left, |_e, window, _cx| {
        window.start_window_move(); // 按住标题栏拖动窗口(交给系统移动)
    })
    .child("自定义标题栏")
}

右键呼出系统窗口菜单(Wayland/X11), 常常就绑在标题栏上:

把边缘命中判断和移动/缩放串起来的典型写法(完整版见 cargo run --example window_shadow):

#![allow(unused)]
fn main() {
.on_mouse_down(MouseButton::Left, move |e, window, _cx| {
    let size = window.window_bounds().get_bounds().size; // 当前窗口尺寸
    match resize_edge(e.position, shadow_size, size) {
        // 落在边上: 系统接管缩放

        // 落在内部: 系统接管移动
        None => window.start_window_move(),

})
}

resize_edge() 就是拿鼠标坐标和四边/四角的命中宽度比大小: 两轴都贴边是角, 只有一轴贴边是边, 都不贴则返回 None. 命中宽度通常取自绘阴影/边框的宽度(见 22.4).

NOTE: 缩放入口是 window.start_window_resize(edge), 没有 cx.start_window_resize(...) 这个方法.

22.4 set_client_inset() 设置客户区内边距

window.set_client_inset(inset) 声明窗口边缘到内容区之间那段“不可见装饰“的宽度, 平台据此把这段区域当装饰处理(Wayland/X11), 让外圈的阴影和缩放手柄不被内容挡住:

#![allow(unused)]
fn main() {
// 渲染开头声明: 四周留 10px 给自绘阴影/边框
window.set_client_inset(shadow_size);
}
  • 参数是一个 Pixels, 四边同宽; 读回用 window.client_inset().
  • window_shadow.rs 里它就是阴影宽度: 内容区外的 10px 既留给圆角阴影, 又是缩放手柄的命中宽度.
  • 配套的 window.set_client_corner_radii(corners) 把客户端画的圆角告诉平台, 让系统效果(如 macOS 阴影)贴合窗口形状.

NOTE: set_client_inset() 收单个 Pixels, 没有 Inset { top, left, right, bottom } 这种结构体, 也不存在按边分别设置的版本.

22.5 窗口阴影

阴影是样式 API, 和 CSS box-shadow 对应. 预设档位 shadow_2xs() 到 shadow_2xl() 、清空用 shadow_none(); 自定义则用 shadow(vec![...]) 装一组 BoxShadow:

#![allow(unused)]
fn main() {
// 自定义阴影
div()
    .shadow(vec![
        // x/y 偏移和颜色: box-shadow: 0 0 #00000066
        gpui::BoxShadow::new(px(0.0), px(0.0), gpui::hsla(0.0, 0.0, 0.0, 0.4))
            .blur_radius(px(5.0)), // 模糊半径: blur 5px
    ])

// 或者直接用预设档位(和 shadow() 二选一)
div().shadow_lg() // 大阴影: box-shadow: 0 10px 15px -3px rgb(0 0 0/0.1), ...
}

BoxShadow::new(offset_x, offset_y, color) 对应 CSS box-shadow 的偏移和颜色, 构造后还有三个可调属性: .blur_radius(px) 模糊半径、.spread_radius(px) 扩散半径、.inset() 改成内阴影.

Client 装饰下系统往往不画窗口外阴影, window_shadow.rs 的做法是自己给窗口容器画一道, 且被平铺贴靠时关掉:

#![allow(unused)]
fn main() {
.when(!tiling.is_tiled(), |div| {
    div.shadow(vec![
        gpui::BoxShadow::new(px(0.), px(0.), Hsla { h: 0., s: 0., l: 0., a: 0.4 })
            .blur_radius(shadow_size/2.), // 模糊半径: blur 5px
    ])
})
}

装饰状态会变(拖到屏幕边缘被平铺、系统外观切换), 两条常用钩子: window.refresh() 标脏触发重绘; cx.observe_window_appearance(window, |_, window, _| window.refresh()) 订阅外观变化(返回 Subscription, 记得 .detach() 或保存住).
